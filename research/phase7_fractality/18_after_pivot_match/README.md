# 18 — Проверка гипотезы разворота: не совпадает ли прогноз лучше с мелким пивотом ПОСЛЕ большого

## 1. Гипотезы

- **H1 (разворот)**: калиброванная S-map (эксп.17f) фактически предсказывает
  не уровень следующего T_big-пивота, а уровень одного из мелких пивотов
  (F или G), которые происходят ПОСЛЕ него — то есть метод «работает» за
  счёт скрытого попадания в мелкий масштаб, а не за счёт содержательного
  прогноза крупного события.
- **H0 (контроль)**: прогноз действительно ближе к целевому T_big-пивоту,
  чем к любому из мелких F/G-пивотов после него, на всех проверяемых
  горизонтах h=1,2,3.

## 2. Концепции, терминология, обозначения

- **T_big=20%** — порог зигзага целевых событий (SBER, 1d), точка, уже
  калиброванная в эксп.17f (`m=3, θ=25.697, T_ratio=0.8987, arm=D_allpeers`).
- **Уровень F** — мелкий зигзаг тем же порогом, что используется для пула
  соседей модели (`T_frac = T_ratio_pool × T_big ≈ 17.97%`).
- **Уровень G** — ещё мельче, `T_tiny = T_big / 7 ≈ 2.86%` (масштаб из
  ранней фазы 7, `research_fractal_scale_sweep`).
- **h** — горизонт итеративного многошагового прогноза (1, 2, 3 T_big-пивота
  вперёд от origin). Механизм — тот же, что в каноническом
  `research/reference/smap_ref.py` (`--steps N`): вектор запроса сдвигается
  на предсказанное плечо предыдущего шага, направление разворачивается,
  пул переотбирается по новому направлению. Модель и пул НЕ меняются
  относительно эксп.17/17m.
- **k** — порядковый номер мелкого (F/G) пивота, найденного ПОСЛЕ даты
  подтверждения h-го фактического T_big-пивота.
- **Окно (window)** — ограничение, докуда «после» ищутся мелкие пивоты:
  - `immediate` — до даты подтверждения (h+1)-го T_big-пивота
  - `extended` — до даты подтверждения (h+2)-го T_big-пивота
  - `unbounded` — без ограничения, первые K пивотов уровня после большого
- **rMAE** = `mean(|pred−actual|) / mean(|persistence−actual|)`, знаменатель
  персистенса — тот же принцип, что в эксп.17 (`level_lp[j] vs level_lp[j-2]`,
  «предыдущее плечо того же уровня повторяется»), применённый к каждому
  уровню (BIG/F/G) отдельно.
- **win-rate** — доля origin×h, где хотя бы одна F/G-альтернатива (по всем
  проверяемым k) даёт МЕНЬШУЮ абсолютную ошибку, чем номинальная цель BIG.

## 3. Методология и протокол

Модель и пул полностью переиспользованы из эксп.17f/17m (без изменений):
S-map, SBER, T_big=20%, D_allpeers (кросс-тикерный пул 45 тикеров),
m=3, θ=25.697, T_ratio(пул)=0.8987. Каузальный контракт не меняется:
целевой ряд и каждый пир физически обрезаются (`arr[:cutoff_idx]`) до
построения зигзага на каждом шаге walk-forward.

F- и G-зигзаги строятся ОДИН РАЗ на полном (необрезанном) ряду — тот же
приём, что уже используется для `full_lp`/`full_conf` самого T_big в
эксп.17: полный ряд используется ТОЛЬКО для разметки фактических точек
сравнения, не участвует в прогнозе.

Для каждого origin `i` (`i ∈ [MIN_HIST=30, n_big-1-N_STEPS-2)`) и каждого
`h=1..3`: прогноз `pred_price_h` (единственное число, кумулятивный
итеративный прогноз) сравнивается с фактическим T_big-пивотом h и с
первыми `k=1..K` F/G-пивотами после его даты подтверждения, в трёх
вариантах окна.

## 4. Параметры

```
TARGET = SBER, T_BIG = 0.20, ARM = D_allpeers
M = 3, THETA = 25.697, T_RATIO_POOL = 0.8987 → T_FRAC ≈ 0.1797
G_RATIO = 1/7 → T_TINY ≈ 0.0286
N_STEPS = 3 (h = 1, 2, 3)
K_F = 2, K_G = 5
WINDOWS = [immediate, extended, unbounded]
```

## 5. Критика постановки

- N_STEPS=3 + extended-окно (+2 больших плеча вперёд для h=3) требует данных
  до `i+5` — выборка сократилась до n=37 (было 42 в одношаговом эксп.17f
  на этой же точке) — тот же порядок малости, предварительный сигнал.
- win-rate некорректно интерпретировать напрямую как «F/G бьёт BIG в 55%
  случаев» — 7 альтернативных кандидатов (F:k=1-2, G:k=1-5) сравниваются
  с ОДНОЙ целью BIG; при случайном шуме и отсутствии реального эффекта
  win-rate >50% ожидаем чисто комбинаторно. Это подтвердилось: rMAE
  (усреднённая метрика, не подверженная этому смещению) показывает
  однозначное преимущество BIG.
- Это диагностика уже существующего прогноза на одном тикере (SBER) —
  выводы не переносились на другие тикеры/масштабы.

## 7. Анализ и выводы

- **H1 (разворот) отклонена, H0 подтверждена**: на всех трёх горизонтах
  абсолютная ошибка прогноза наименьшая именно к T_big-пивоту — как в
  абсолютных рублях (20.8 vs 27-66 для любой F/G-альтернативы на h=1), так
  и после нормировки на persistence (rMAE 0.61-1.23 для BIG против
  1.1-8.5 для F/G). Разрыв растёт с h — прогноз не «незаметно» целится в
  мелкий масштаб на дальних горизонтах, а наоборот, остаётся ближе всего к
  большому.
- **win-rate ~55-57% — не сигнал, а артефакт множественного сравнения**:
  7 альтернативных кандидатов против 1 цели дают win-rate >50% и при
  отсутствии реального эффекта; согласуется с тем, что усреднённая rMAE
  (не подверженная этому смещению) показывает однозначное превосходство
  BIG.
- **rMAE F/G растёт с k** (особенно у G: 1.7→4.9 от k=1 к k=5 на h=1) —
  прогноз не «дрейфует» к какому-то определённому мелкому пивоту дальше по
  цепочке, ошибка просто растёт, что типично для несвязанной с
  мелкомасштабной структурой случайной величины.
- **Практический вывод**: текущая интерпретация эксп.17 (модель
  предсказывает крупный пивот, а не мелкий) не вводит в заблуждение —
  можно продолжать оценивать результат fase 7 по T_big-метрике без
  дополнительной оговорки о скрытой мелкомасштабной цели.

## 8. Дальнейшие направления

- Проверка на других тикерах (Stage2-набор из эксп.17b) — сейчас только
  SBER, единичный тикер.
- Если интересно продолжать линию «мелкая структура после большого
  пивота» — эксп.17n (визуальная разведка «мелкий T_tiny зигзаг в окне
  прогноза») уже отметил потенциальный трейлинг-сигнал перед разворотом на
  длинных движениях; это отдельная, более многообещающая гипотеза, чем
  проверенная здесь.
- Гипотеза формально закрыта для данной конфигурации (SBER, T_big=20%,
  калиброванная S-map) — открывать вновь только при существенном изменении
  модели/масштаба.
