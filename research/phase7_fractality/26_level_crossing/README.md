# 26 — Сетка уровней log-цены (level crossing, R=1)

## 1. Гипотезы

- Наблюдение пользователя: событийная концепция (зигзаг) частично приводит ряд
  к стационарному виду ПО ВРЕМЕНИ (сэмплирует по достижению состояния, а не по
  такту календаря) — в отличие от классической стационаризации ПО ЗНАЧЕНИЮ
  (logtrend, SSA, z-score), которую всегда пробовали раньше. Зигзаг, однако,
  всё ещё зависит от подтверждения-с-откатом (порог T).
- Проверяем самую чистую версию идеи: событие = момент пересечения соседнего
  уровня фиксированной сетки Δ по log-цене, БЕЗ фильтра разворота (R=1) —
  разворот на 1 уровень так же лёгок, как продолжение.
- Следствие фиксированного шага: амплитуда следующего события перестаёт быть
  случайной величиной (всегда ровно Δ) — объект прогноза меняется с "куда и
  насколько" (регрессия амплитуды, как в зигзаге) на "в какую сторону"
  (направление, классификация).
- Многошаговый прогноз запрошен сразу (не только H=1): рекурсивный, по
  событиям (не по барам) — предсказанное направление шага h используется,
  чтобы сдвинуть окно вложения для предсказания шага h+1.

## 2. Концепции, терминология, обозначения

- **Δ (шаг сетки)** — расстояние между соседними уровнями в log-цене,
  `L_k = k·Δ`.
- **R=1** — режим без фильтра разворота: подтверждение перехода на соседний
  уровень (в любую сторону) не требует ничего, кроме факта достижения этого
  уровня (в отличие от классических range bars/P&F, где для разворота обычно
  нужно пройти несколько боксов подряд — упоминается только как источник идеи,
  не как заимствованный трейдерский приём).
- **events/бар** — среднее число событий на один календарный бар. При
  events/бар > 1 большинство событий происходят ВНУТРИ одного бара — их
  порядок не наблюдаем напрямую (только OHLC), это артефакт конвенции, не
  реальная рыночная информация.
- **H (горизонт)** — число СОБЫТИЙ вперёд (не баров) для рекурсивного
  прогноза.
- **smap_acc / persist_acc / coin** — доля верно угаданных направлений:
  калиброванная S-map модель / наивное "повторить последнее направление" /
  теоретическая монета (0.5).
- **price rMAE** — как и раньше: `mean(|pred-actual|)/mean(|persistence-actual|)`,
  но persistence здесь = "повторить последнее известное направление H раз" —
  НЕ формула из `feedback_rmae_persistence.md` (та обоснована для
  АЛЬТЕРНИРУЮЩИХ зигзаг-пивотов; уровневые события чередуются не строго,
  frac_reversal≈0.4-0.5, поэтому естественный naive-baseline здесь —
  momentum-continuation, не "вернуться к предыдущему экстремуму").

## 3. Методология и протокол

SBER (1d), без кросс-тикерного пула (решение пользователя — слишком радикальная
смена конструкции событий, чтобы сразу мешать с пулом). Без фильтрации пула по
направлению query-события (в отличие от зигзаг-экспериментов 17-25 — то
разделение было специфично для асимметрии зигзага, здесь обоснования пока нет).

Каузальный контракт — тот же принцип, что exp17/21/23/24/25: прогноз на каждом
origin строится на данных, обрезанных ФИЗИЧЕСКИМ СРЕЗОМ массивов
(`arr[:cutoff_idx]`). Полная (необрезанная) последовательность используется
только для перечисления origin'ов и получения "правильного ответа".
Каузальность самого детектора (обрезка+rebuild = точно префикс полного
прохода) проверена ЭМПИРИЧЕСКИ на 7 точках среза (0 расхождений) — по явному
требованию пользователя (см. эксп.25), не только рассуждением.

Три фазы:
1. **Диагностика масштаба** — events/бар и frac_reversal по сетке Δ, чтобы
   отсеять артефактные (внутрибарные) значения Δ.
2. **Быстрая проверка** — фиксированные m=3, θ=1.0, без калибровки, подвыборка
   300 origin'ов на рабочую сетку Δ.
3. **Полная калибровка + многошаговый прогноз** — на 2 лучших по rMAE Δ,
   подвыборка 800 origin'ов, покоординатный спуск (m, θ), затем рекурсивный
   прогноз на H=1,3,5,10 событий вперёд.

Подвыборка origin'ов (а не полный перебор) — компромисс ради компьютера: при
мелких Δ число событий (и, соответственно, origin'ов) — тысячи, что для
честного walk-forward с полным rebuild на каждом origin было бы неоправданно
долго. Это НЕ уступка каузальности (каждый origin по-прежнему обрабатывается
через полную обрезку+rebuild) — просто меньше origin'ов проверяется.

## 4. Параметры

```
DELTA_ILLUSTRATION = [0.005, 0.008, 0.013, 0.02]   # только диагностика (артефакт)
DELTA_GRID         = [0.032, 0.05, 0.08, 0.13, 0.20]  # рабочая сетка (events/бар<1)
MIN_HIST = 30, H_LIST = [1,3,5,10], HMAX=10
N_ORIGINS_QUICK=300, N_ORIGINS_FULL=800, N_TOP_DELTAS=2
M_GRID=[2,3,4,5], THETA∈[0,32] (golden section, tol=0.1), MAX_OUTER=5
DEF_M=3, DEF_THETA=1.0 (для быстрой проверки, без калибровки)
```

## 5. Критика постановки

- **events/бар > 1 на мелких Δ (0.005-0.02)** — порядок внутрибарных событий
  целиком определяется придуманной конвенцией (net_up/net_down по знаку
  close-open), а не наблюдаемым путём цены. Эти Δ полностью исключены из
  рабочей сетки и оценки, использованы только для иллюстрации проблемы.
- **Persistence-baseline пересмотрен** (см. §2) — обоснованное отступление от
  установленной формулы зигзага, но это значит, что rMAE здесь НЕ напрямую
  сравним с rMAE зигзаг-экспериментов (17-25) даже на одном и том же тикере —
  разные знаменатели.
- **Без разбивки пула по направлению query** — упрощение первого прохода;
  возможно, отдельные модели для "текущий тренд вверх"/"вниз" работали бы
  лучше (как в зигзаге), не проверялось.
- **Подвыборка origin'ов** — только компромисс по производительности (см. §3),
  но означает, что итоговые числа основаны на выборке (49-405 origin'ов в
  зависимости от Δ), не на полном множестве доступных origin'ов.
- **θ на калибровке упёрлась в границу диапазона поиска (31-32 из [0,32])** —
  сильный диагностический сигнал: модель тянется к максимальной локальности
  (почти nearest-neighbor), что обычно означает отсутствие гладкой предсказуемой
  зависимости в признаках, а не найденную структуру. Диапазон не расширялся
  (проверить, продолжится ли рост при THETA_HI>32, не делали).
- **Многошаговый rMAE убывает с ростом H** — не обязательно означает рост
  точности прогноза; вероятная причина — baseline "повторить направление H раз
  подряд" деградирует БЫСТРЕЕ, чем растёт ошибка модели, поскольку реальные
  события меняют направление в ~45% случаев (наивное монотонное продолжение —
  всё более плохой baseline на длинных горизонтах). Это не проверено отдельно
  (не считали абсолютную, а не относительную ошибку модели по H).

## 7. Анализ и выводы

- **Устойчивого преимущества по направлению не найдено.** accuracy колеблется
  вокруг или НИЖЕ 0.5 почти на всех Δ и H; там, где выше (Δ=0.032 H=1:
  0.449>0.393 vs persist на ЭТОЙ выборке; Δ=0.200 H=1: 0.531>0.500) — эффект
  в пределах шума при n=49-405 и не подтверждается на других H той же серии.
- **θ систематически упирается в верхнюю границу диапазона поиска** (31.0,
  31.8 из [0,32]) на ОБОИХ откалиброванных Δ — сильный диагностический
  сигнал: нет гладкой предсказуемой зависимости, модель "убегает" к
  ближайшим соседям, что типично при отсутствии структуры, а не признак
  найденного сигнала.
- **Убывание price rMAE с ростом H — вероятно, артефакт деградирующего
  baseline**, а не растущая точность модели (см. критику §5). Числа H>1
  нельзя интерпретировать как "модель лучше предсказывает на большем
  горизонте".
- Гипотеза пользователя о "стационаризации по времени" как объяснении
  интересных результатов зигзага НЕ опровергнута и НЕ подтверждена этим
  экспериментом — скорее показывает, что просто "время-стационарная выборка"
  недостаточна сама по себе: зигзагу помогает что-то ЕЩЁ (подтверждение
  разворота с реальным откатом, отбор "значимых" экстремумов), чего у чистой
  сетки уровней нет.
- Итог, соотносящийся с продолжающимся паттерном сессии: очередная попытка
  переосмыслить конструкцию событий (после SSA-21, logtrend-24, adaptive-25 —
  все отрицательные) тоже не дала явного улучшения — но здесь это не попытка
  "почистить вход", а принципиально другая архитектура прогноза, поэтому
  зачисляется в отдельную категорию, не как 4-я подряд неудача той же идеи.

## 8. Дальнейшие направления

- Проверить R>1 (классический P&F-стиль: продолжение — 1 уровень, разворот —
  R уровней) — может устранить дребезг без полного отказа от идеи чистой
  сетки.
- Расширить диапазон поиска θ выше 32, чтобы понять, есть ли содержательный
  максимум, или зависимость монотонно растёт до бесконечности (ещё один
  признак отсутствия сигнала, если растёт неограниченно).
- Разбивка пула по направлению query-события (как в зигзаге) — не пробовали.
- Признаки на основе абсолютных log-diff (сейчас) vs направление (±1) как
  отдельный признак — не пробовали по отдельности.
- Учитывая слабость результата — низкий приоритет без нового веского
  аргумента, если только не пробовать R>1 как обоснованную вариацию.
