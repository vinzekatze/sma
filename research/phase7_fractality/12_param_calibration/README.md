# 12 — Покоординатная калибровка параметров LWR (эксперимент A)

## Гипотезы

**H1.** Покоординатный спуск находит параметры (m, T_ratio, K), дающие меньший rMAE на hold-out периоде, чем фиксированные дефолты (m=2, T_ratio=0.85, K=75).

**H2.** Скользящая перекалибровка (каждые R шагов) адаптируется к режимным изменениям и превосходит однократную калибровку на начальном окне.

**H3.** Ограничение пула N_max (recency window) улучшает результат — пул перестаёт разбавляться устаревшими событиями.

## Концепции и обозначения

| Символ | Смысл |
|---|---|
| `m` | Размерность вложения: длина вектора лог-доходностей запроса |
| `T_ratio` | Отношение T_pool / T_big; T_pool = T_ratio × T_big |
| `K` | Число соседей в LWR (Gaussian kernel, bandwidth = d_max) |
| `N_cal` | Размер калибровочного окна (число T_big-пивотов) |
| `R` | Интервал перекалибровки (число шагов между пересчётами) |
| `N_max` | Максимальный размер пула на каждом шаге (recency window); None = без ограничения |
| `rMAE` | mean(|err|) / mean(|diff(actuals)|) — метрика качества |

**Покоординатный спуск:** оптимизируем по одному параметру, остальные фиксированы. Повторяем цикл до сходимости (параметры не изменились) или до max_outer итераций.

- **K**: тернарный поиск в `[K_lo, K_hi]` (целочисленный)
- **T_ratio**: метод золотого сечения в `[T_lo, T_hi]` (непрерывный)
- **m**: полный перебор `{2, 3, 4, 5}`

**Тёплый старт:** при каждой перекалибровке начинаем с предыдущих оптимальных параметров.

## Методология и протокол

1. Загружаем все свечи, строим T_query зигзаг один раз.
2. T_pool зигзаги строятся «лениво» и кэшируются по значению T_pool (с точностью 4 знака).
3. Первая калибровка: шаги `[MIN_HISTORY, MIN_HISTORY + N_cal)`.
4. Первый прогноз: шаги `[MIN_HISTORY + N_cal, ...)`.
5. Каждые R шагов: скользящая перекалибровка на окне `[i - N_cal, i)`.
6. На каждом шаге прогнозируем одним шагом вперёд (H=1) с текущими параметрами.

Сравнение: адаптивные параметры vs фиксированные дефолты (m=2, T_ratio=0.85, K=75) на одном walk-forward.

## Критика постановки

1. **Калибровка в выборке.** rMAE на калибровочном окне — это обучающая метрика (walk-forward внутри того же окна). Возможен оверфиттинг параметров к конкретному периоду, который не обобщается на следующие R шагов.

2. **Предположение унимодальности.** Тернарный поиск и золотое сечение предполагают унимодальную зависимость rMAE(K) и rMAE(T_ratio). Если поверхность потерь многомодальна (что вероятно), алгоритм найдёт локальный минимум.

3. **Взаимозависимость параметров.** Оптимальные K и T_ratio могут зависеть друг от друга; покоординатный спуск не гарантирует нахождение глобального оптимума при сильных взаимодействиях.

4. **Малый пул при маленьких T.** При N_max=None и малом T (много пивотов) — пул растёт, и со временем давние нерелевантные события разбавляют сигнал. N_max решает это, но сам требует подбора.
