# 13 — Офлайн-калибровка параметров: LWR vs S-map

## Гипотезы

**H1.** Покоординатный спуск на полной истории (walk-forward по всем пивотам) находит параметры (m, K/θ, T_ratio) лучше, чем дефолты.

**H2.** LWR и S-map при оптимальных параметрах дают существенно разный rMAE — один метод превосходит другой.

**H3.** Оптимальные T_ratio и m совпадают для обоих методов (параметры определяются структурой данных, а не методом).

## Концепции и обозначения

| Символ | Смысл |
|---|---|
| `T_BIG` | Порог зигзага запроса (query, 4%) |
| `T_pool = T_ratio × T_BIG` | Порог зигзага пула (фрактальный масштаб) |
| `m` | Размерность вложения: длина вектора лог-доходностей |
| `K` | Число соседей LWR (Gaussian kernel, bandwidth = d_max) |
| `θ` | Параметр локализации S-map: w = exp(−θ · d / mean_d) |
| `N_steps` | Число шагов прогноза = 1 (H=1) |
| `rMAE` | mean(|err|) / mean(|Δactuals|): ошибка в долях типичного размаха зигзага |

**Каузальный контракт**: на шаге i алгоритм использует только события пула, у которых
подтверждён следующий пивот: `pool_conf[j+1] < query_conf[i]`. Это гарантирует,
что и признаки (lp[j]) и цель (lp[j+1]) были известны до текущего момента.

**Покоординатный спуск**: фиксируем два параметра, оптимизируем третий, повторяем до сходимости:
- `m` — полный перебор {2, 3, 4, 5}
- `K` — тернарный поиск на [10, 300] (целочисленный)
- `θ` — золотое сечение на [0, 20] (непрерывный)
- `T_ratio` — золотое сечение на [0.65, 1.0] (непрерывный)

## Методология и протокол

1. Загрузить все свечи SBER 10m.
2. Построить T_query зигзаг один раз на всех данных.
3. T_pool зигзаги строятся лениво и кэшируются по T_pool (5 знаков).
4. Walk-forward: для каждого query-пивота i (в порядке времени):
   - Отсечка пула: `pool_conf[j+1] < query_conf[i]`
   - Фильтр направления: только события с `pool_dir[j] == query_dir[i]`
   - Прогноз → ошибка
5. rMAE = mean(|err|) / mean(|step_size|) по всем состоявшимся прогнозам.
6. Оптимизировать (m, K, T_ratio) для LWR и (m, θ, T_ratio) для S-map.
7. Сравнить: default vs optimal для каждого метода, LWR vs S-map.

## Параметры запуска

| Параметр | Значение |
|---|---|
| Тикер / интервал | SBER / 10m |
| T_BIG | 0.04 (4%) |
| M_VALUES | {2, 3, 4, 5} |
| K_LO / K_HI | 10 / 300 |
| T_LO / T_HI | 0.65 / 1.0 (T_ratio) |

| THETA_LO / THETA_HI | 0.0 / 20.0 |

| Defaults S-map | m=2, θ=2.0, T_ratio=0.85 |

## Критика постановки

1. **In-sample оптимизация.** Walk-forward по всей истории — это всё ещё in-sample для будущих данных. Параметры, найденные на SBER 2018–2026, могут не обобщаться на другие периоды или тикеры.

2. **Покоординатный спуск — локальный минимум.** Алгоритм не гарантирует глобальный оптимум при взаимозависимости параметров. Сходимость трассы выводится для диагностики.

3. **Разные N_steps для LWR и S-map.** LWR требует ≥ K пула → пропускает ранние шаги. S-map требует ≥ max(m+2, 4) → начинает раньше. Числа n_steps будут разными.

4. **Непрерывный θ.** Золотое сечение предполагает унимодальность rMAE(θ). В эксперименте 12 θ был нестабилен — унимодальность сомнительна. Результат трассы покажет.

## Результаты

### T=4% (786 пивотов, 667–779 оценочных шагов)

| Метод | default rMAE | optimal rMAE | Δ% | m | K/θ | T_ratio |
|---|---|---|---|---|---|---|
| LWR | 0.3844 | **0.3770** | −1.9% | 2 | K=162 | 0.885 |
| S-map | 0.3893 | 0.3868 | −0.7% | 2 | θ=0.82 | 0.905 |

Время калибровки: ~17s. Сходимость за 2–3 итерации.

### T=1% (9469 пивотов, ~9000 оценочных шагов) — стресс-тест

| Метод | default rMAE | optimal rMAE | Δ% | m | K/θ | T_ratio |
|---|---|---|---|---|---|---|
| LWR | 0.3897 | 0.3852 | −1.2% | 3 | K=400 | 0.816 |
| S-map | 0.3857 | **0.3834** | −0.6% | 4 | θ=2.83 | 0.818 |

Время калибровки: ~20 мин. Сходимость за 3–4 итерации.

Файлы: `results/calibration_SBER_10m_T004.json`, `results/calibration_SBER_10m_T001.json`

## Анализ и выводы

**H1 подтверждена частично.** Калибровка даёт −0.6%…−1.9% к rMAE. Выигрыш скромный, но стабильный и воспроизводимый. При T=4% алгоритм сходится за 2–3 итерации, при T=1% за 3–4.

**H2 подтверждена с оговоркой.** Победитель зависит от масштаба:
- T=4% (мало событий): **LWR** лучше (0.3770 vs 0.3868). Мало событий → меньше пользы от локализации → θ→0 (S-map вырождается в OLS) → LWR с гауссовым ядром точнее.
- T=1% (много событий): **S-map** лучше (0.3834 vs 0.3852). Плотный пул → θ=2.83 реально находит локальную структуру.

**H3 частично подтверждена.** T_ratio стабилен (~0.82–0.89 независимо от метода). m растёт с уменьшением T: 2 (T=4%) → 3/4 (T=1%) — при мелком масштабе нужно больше контекста.

**N_max не нужен.** Если бы старые события разбавляли пул, оптимизатор выбрал бы малый K (чтобы брать только ближайших). Напротив, K растёт (162→400) — алгоритм хочет больше истории, не меньше.

**K=400 — interior optimum**, не граница (K_HI=500). Ternary search сошёлся внутри диапазона.

**rMAE почти не меняется между масштабами** (0.377–0.384). Это хороший знак: фрактальная структура зигзага одинаково выражена на разных масштабах.

## Дальнейшие направления

- Зафиксировать m=2 (стабильный) и искать только (K/θ, T_ratio) — проверить устойчивость
- Проверить найденные параметры на других тикерах (GAZP, LKOH, MTSS)
- Если оптимальное θ ≈ 0 → S-map вырождается в OLS → метод неэффективен для этих данных
