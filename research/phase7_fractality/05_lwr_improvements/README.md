# Эксперимент 05 — Улучшения LWR для событийной фрактальности

**Скрипт:** `05_lwr_best.py`  
**Дата:** 2026-06-29  
**Данные:** SBER 10m  

---

## 1. Гипотезы

1. Убрав ценовой уровень из поиска соседей (srch=diff), можно улучшить rMAE — направление движения важнее абсолютной позиции.
2. Отфильтровав соседей только по одному направлению (HIGH или LOW), мы уберём «шум» противоположных событий.
3. Оптимальное K при dir_filter выше, чем без него (больший эффективный пул при разбиении пополам).
4. Z-score для пула с T_FRAC ≈ T_BIG не нужна: Δ1 и Δ2 уже на одной шкале (оба — лог-движения по одному порогу).

---

## 2. Концепции, терминология, обозначения

| Символ | Описание |
|--------|----------|
| T_BIG | Порог «большого» зигзага в лог-пространстве (0.04 ≈ 4.08% в ценах) |
| T_FRAC | Порог «фрактального» пула (0.036 ≈ 3.67%) |
| H | Горизонт прогноза (H=1 событие зигзага вперёд) |
| P | Размерность эмбеддинга; P=3 → 2D diff-вектор [Δ1, Δ2] |
| K | Число ближайших соседей для LWR |
| lp_big | Log-цены пивотов T_BIG-зигзага |
| lp_f1 | Log-цены пивотов T_FRAC-зигзага (пул) |
| Δ1 | lp[i] − lp[i-1] (последнее движение) |
| Δ2 | lp[i-1] − lp[i-2] (предыдущее движение) |
| dir_filter | Фильтр: брать только соседей того же направления (HIGH/LOW) |
| srch=diff | Поиск соседей по diff-фичам [Δ1, Δ2], без ценового уровня |
| y_rel | lp_f1[j+H] − lp_f1[j] — относительный лог-сдвиг (метка) |
| pred | exp(lp_big[step] + pred_rel) — прогноз в ценах |
| rMAE | mean(|ошибка|) / mean(|Δactuals|) в исходных ценах |
| LWR | Locally Weighted Regression с Гауссовым ядром, xi = d_max(K-й сосед) |

**Зигзаг в лог-пространстве:**  
Порог аддитивный: `log(high) − last_low >= T`. При T=0.04: exp(0.04)−1 ≈ 4.08% в ценах. Пивот записывается в день достижения экстремума (`dates[ext_idx]`), а не в день подтверждения разворота.

**Вектор задержек:** P=3 даёт cols=[lp, Δ1, Δ2]; для поиска и LWR используются только cols[1:] = [Δ1, Δ2] без нормализации.

---

## 3. Методология и протокол

Walk-forward по шагам T_BIG-зигзага:
1. Для шага `step` (текущий пивот) строим каузальный пул T_FRAC-событий: все пивоты с датой < `dt_big[step]`.
2. `dir_filter`: отбираем только пивоты того же направления (HIGH или LOW).
3. Вычисляем diff-фичи [Δ1, Δ2] для пула и запроса — без нормализации.
4. K=75 ближайших соседей по L2-расстоянию в raw-пространстве.
5. LWR (Гауссово ядро, xi = d_max) → `pred_rel`.
6. `pred = exp(lp_big[step] + pred_rel)`.
7. `actual = exp(lp_big[step + H])`.

Метрика: rMAE = mean(|pred − actual|) / mean(|diff(actual)|).  
Референс (4-way ensemble из `zigzag_forecast_ref.py`): rMAE = 0.3911.  
Стартовая точка (exp.01, z-score, K=50): rMAE ≈ 0.3861.

## 5. Критика постановки

**Потенциальная look-ahead проблема в зигзаге.** Дата пивота — день достижения экстремума (`dates[ext_idx]`), но подтверждается пивот только позже (когда цена уйдёт на T в обратную сторону). Это значит, что T_FRAC-пивоты с датой между `ext_idx` и баром подтверждения формально «из будущего» относительно момента, когда мы реально знаем о пивоте. Требует жёсткого теста (см. дальнейшие направления, п.1).

**Единственный тикер.** Все результаты на SBER 10m. Обобщаемость не проверена.

**T_FRAC ≈ T_BIG.** Пул на 3.6% при запросе 4% даёт ratio ≈ 1.4×. Это ближе к «тот же» масштаб, чем к «иерархически меньший». Выигрыш может быть не фрактальной природы, а следствием чуть бо́льшего пула.

**dir_filter как жёсткий срез.** При очень маленьком пуле fallback снимает фильтр — это может вносить непоследовательность.

## 7. Анализ и выводы

1. **srch=diff** — наибольший вклад. Ценовой уровень в пространстве поиска добавляет шум: два события с похожими движениями, но разными абсолютными ценами, должны быть соседями.

2. **dir_filter** — второй по вкладу. Зигзаг детерминированно чередует HIGH/LOW; смешивание направлений в пуле — это прогноз рыночного движения по противоположному движению, что концептуально неверно.

3. **Raw > z-score.** Δ1 и Δ2 — лог-движения с одним порогом T, поэтому уже на сравнимой шкале. Z-score уравнивает дисперсии и тем самым искусственно «равноправит» лаги, хотя более свежее движение Δ1 должно быть «весомее» в L2-метрике.

4. **Нелинейные альтернативы не помогают.** В 2D-пространстве [Δ1, Δ2] при K=75 соседях RBF и Simplex работают близко к LWR или хуже. Дополнительная нелинейность не компенсирует малое число информативных измерений.

5. **Пул на T_FRAC=0.85×T_BIG оптимален** (ранее установлено в exp.01-03). Слишком мелкий T_FRAC → несовместимый масштаб движений.

## 8. Дальнейшие направления

### Проверки

1. **Жёсткий тест каузальности.** Заменить дату пивота на дату подтверждения (бар, где зафиксирован разворот) в качестве cutoff для пула. Если rMAE заметно меняется — есть look-ahead.

2. **Midprice-зигзаг.** Построить зигзаг на `(high+low)/2` (или `(open+close)/2`) в режиме «точка-точка». Это устраняет асимметрию high/low, упрощает перенос на нефинансовые ряды и позволяет проводить сравнение со стандартными 1D-методами.

### Алгоритмические направления

3. **Адаптивный выбор фрактального уровня.** Рассчитывать локальную фрактальную размерность ряда в точке прогноза (log-цена) и выбирать T_FRAC на её основе вместо фиксированного 0.036.

4. **Ансамблирование.** Объединить прогнозы нескольких T_FRAC уровней (например, 0.85×T, 0.7×T, 1.0×T). Оба направления: взвешенное среднее и stacking.

5. **Онлайн-обучение по последним событиям.** Взвесить пул в пользу свежих событий (временно́й decay) или переобучать LWR только на N последних событиях аналогично rolling window.
