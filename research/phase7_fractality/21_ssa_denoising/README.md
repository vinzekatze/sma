# 21 — SSA-очищенные vs шумные пивоты: какие предсказуемее в принципе?

## 1. Гипотезы

- **H1**: сравниваем не абсолютную точность прогноза, а ОТНОСИТЕЛЬНОЕ
  улучшение над собственным persistence — отдельно для пивотов на сыром
  (шумном) log(midprice) и на SSA-очищенном log(midprice). Если
  SSA-пивоты дают БОЛЬШЕЕ относительное улучшение — структура сильнее у
  «настоящих» разворотов, шумовые пивоты размывают предсказуемость. Если
  сырые не хуже (или лучше) — мелкие движения тоже несут информацию,
  «шума» в чистом смысле может не быть.
- Переформулировка эксперимента из `research/phase6_attractor/zigzag_event_time`
  (SSA на ratio, скр. `zigzag_direct_forecast.py`) — там T фиксировали
  одинаковым для no_ssa/k=2/k=3, из-за чего SSA-условия теряли 35%
  пивотов (confound: смешивалось «эффект SSA» и «эффект меньшей выборки»),
  и числа rMAE были посчитаны ДО исправления формулы persistence
  ([[feedback-rmae-persistence]]) — то есть вдвойне ненадёжны.

## 2. Концепции, терминология, обозначения

- **midprice** = (open+close)/2 — усреднение убирает часть tick-шума
  (предпочтение, установленное в Direction A, [[research-ssa-preprocessing]]).
- **SSA (Singular Spectrum Analysis), каузальная скользящая** — на каждом
  баре t берётся траекторная матрица (матрица Ханкеля) из log(midprice)
  за окно [t-W+1, t], SVD, реконструкция k главными компонентами, берётся
  только последний элемент (Xr[K_m-1, L-1]) — то же, что `_ssa_smooth_ratio`
  в prototype/forcaster/ui/app6.py, реализовано заново самостоятельно
  (research-скрипты не зависят от prototype). W=256, L=8.
- **Условия**: `raw` (без SSA) / `ssa_k1` (k=1, сильное сглаживание) /
  `ssa_k2` (k=2, умеренное).
- **Зигзаг на ОДНОЙ серии** (не high/low, как в остальной фазе 7) —
  midprice после усреднения O/C уже не имеет отдельного high/low;
  используется упрощённый однорядный зигзаг (тот же порядковый принцип,
  что и high/low-версия, но по одной серии).
- **N_TARGET=73** — целевое число пивотов для подбора T_big каждого
  условия (масштаб, привычный по всей сессии эксп.17-20 — high/low
  SBER@T_big=20% даёт 73 пивота; midprice-зигзаг даёт заметно меньше при
  том же T, поэтому T_big подбирается заново для ВСЕХ трёх условий).

## 3. Методология и протокол

SBER, кросс-тикерный пул D_allpeers (45 тикеров, тот же механизм отбора
пиров по датам/корреляции, что и в эксп.17 — не зависит от предобработки
зигзага). Пиры проходят ТУ ЖЕ предобработку (midprice/SSA), что и целевой
тикер — для консистентности условия.

Шаг 1 — грубый грид T_big∈[0.06, 0.30] (шаг 0.01) для каждого условия,
выбор T_big с числом пивотов ближайшим к N_TARGET=73.
Шаг 2 — покоординатный спуск (m→θ→T_ratio), тот же алгоритм, что
`17f_calibrator.py`, независимо для каждого условия.
Шаг 3 — rMAE каждого условия относительно СВОЕГО persistence (исправленная
формула, `feedback_rmae_persistence.md`) — сравниваются коэффициенты
улучшения, не абсолютные числа напрямую.

## 4. Параметры

```
TARGET=SBER, ARM=D_allpeers
SSA_W=256, SSA_L=8, SSA_KS=(1,2)
N_TARGET=73, TBIG_SEARCH_GRID=[0.06..0.30] шаг 0.01
M_GRID=[2,3,4,5], THETA∈[0,32], T_ratio∈[0.50,0.95]
MIN_HIST=30
```

## 5. Критика постановки

- Только SBER, один набор SSA-параметров (W=256, L=8) — не проверено на
  других тикерах/масштабах окна.
- T_ratio для ssa_k1 (0.505) уткнулся в нижнюю границу поиска (0.50) —
  истинный оптимум может быть ещё ниже; не меняет качественный вывод
  (ssa_k1 всё равно худший из трёх), но абсолютное значение rMAE для
  ssa_k1 может быть слегка занижено (в пользу худшего результата, то есть
  вывод консервативен, не завышен).
- n_eval=42-44 — та же малая выборка, что и весь эксп.17-20, предварительный
  сигнал, не строгое доказательство.
- Одноразовый подбор T_big по пивот-каунту (не по чему-то более
  содержательному) — простой, но грубый критерий сопоставимости условий.
- SSA warmup (первые W-1=255 баров без сглаживания) уменьшает эффективную
  историю на ~5 лет из ~19 доступных — не должно сильно искажать результат
  при таком масштабе истории, но не проверялось отдельно.

## 7. Анализ и выводы

- **Шумные (raw) пивоты предсказуемы ЛУЧШЕ, чем SSA-очищенные — монотонно
  по силе сглаживания**: raw (0.614) < ssa_k2 (0.664) < ssa_k1 (0.732).
  Полностью честное сравнение (одинаковое число пивотов ~73-75, T_big
  подобран отдельно для каждого условия, m/θ/T_ratio откалиброваны
  отдельно, rMAE относительно СВОЕГО persistence).
- **H1 отклонена в направлении, противоположном интуиции об «очищении
  шума»**: SSA не обнажает более предсказуемое ядро разворотов — она
  устраняет вместе с «шумом» и полезную для событийного прогноза
  структуру. Чем агрессивнее сглаживание, тем хуже относительная
  предсказуемость.
- **Косвенный ответ на вопрос «есть ли шум на бирже вообще»**: похоже, что
  того, что можно было бы чисто отделить и выбросить как «неинформативный
  шум», в этом смысле нет — мелкие движения несут структуру, релевантную
  для событийного прогноза, не менее (и по этим данным даже более)
  ценную, чем крупные «настоящие» развороты.
- Согласуется с более ранней находкой сессии про хаотичную пороговую
  чувствительность зигзага (эксп.19e, «эффект бабочки» T_live) — мелкие
  движения не случайный шум поверх «истинного» сигнала, а часть той же
  структуры, определяющей, где физически окажется следующий разворот.

## 8. Дальнейшие направления

- Проверить на других тикерах (хотя бы 2-3 из уже откалиброванного набора
  17r) — устойчив ли монотонный паттерн raw>ssa_k2>ssa_k1 за пределами
  SBER.
- Расширить T_ratio-поиск ниже 0.50 для ssa_k1, чтобы исключить эффект
  границы поиска.
- Проверить другие SSA-окна (W) — возможно, при другом масштабе
  сглаживания (короче окно, ближе к локальному tick-шуму, а не к
  недельным/месячным трендам) результат изменится.
- Если направление подтвердится на нескольких тикерах — это довольно
  сильный аргумент против любых будущих идей "почистить входной ряд перед
  зигзагом" в этом пайплайне.
