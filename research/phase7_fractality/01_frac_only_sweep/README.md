# 01_frac_only_sweep — Свип T_frac: пул только из фрактальных событий

**Дата:** 2026-06-28  
**Тикер:** SBER 10m  
**Скрипт:** `01_frac_only_sweep.py`

---

## 1. Гипотезы

**Г1.** Пул, составленный исключительно из событий меньшего масштаба T_frac, способен предсказывать следующее событие масштаба T_big.

**Г2.** Существует оптимальное соотношение T_frac / T_big, при котором frac-only пул бьёт baseline (LWR на T_big событиях).

**Г3.** При очень малых T_frac (ratio >> 1) scale mismatch в embedding-е уничтожает полезный сигнал.

---

## 2. Концепции, терминология, обозначения

| Термин | Определение |
|--------|-------------|
| T_big | Порог зигзага для целевых событий (те, что прогнозируем) |
| T_frac | Порог зигзага для пула соседей (фрактальный масштаб) |
| frac-only | Режим: в пуле нет T_big событий, только T_frac |
| baseline LWR | LWR с пулом из T_big событий (без фрактала) |
| ratio | n_small / n_big — плотность фрактального пула относительно целевого |
| mean_d | Среднее евклидово расстояние от запроса до его K соседей в нормированном пространстве |
| scale mismatch | Несовпадение масштабов log-return колонок embedding-а: query col 1,2 ≈ ±T_big%, pool col 1,2 ≈ ±T_frac% |
| sanity check | T_frac = T_big: frac-only совпадает с baseline по определению |

**Embedding:** `X[i] = [prices[i], ln(p[i]/p[i-1]), ln(p[i-1]/p[i-2])]`, p=3, hybrid (value + log-returns).

**Метка y:** `p_small[j+1]` — следующий T_frac пивот (H=1 в фрактальном времени). Систематически смещена относительно цели (`p_big[step+1]`), но одинаково для всех T_frac — форма кривой rMAE(T_frac) не искажена.

**Нормализация:** joint z-score по пулу + запрос (`X_pool.mean(0)`, `X_pool.std(0)`).

---

## 3. Методология и протокол

Walk-forward по T_big событиям:
- Для каждого шага `step` (начиная с MIN_HISTORY=50):
  - Запрос: `X_big[step]` (embedding из T_big ряда)
  - Пул: T_frac события с датой строго до `dt_big[step]` (causal gate через searchsorted)
  - LWR: K=50 ближайших соседей, Gaussian kernel `w=exp(-0.5*(d/xi)²)`
  - Предсказание сравнивается с `p_big[step+1]`
- Метрика: rMAE = MAE(pred, actual) / mean(|diff(actual)|)

Параллельно: baseline LWR с пулом из T_big событий (label = `p_big[j+1]`).

## 5. Критика постановки

**Смещение метки.** `y = p_small[j+1]` предсказывает следующий T_frac пивот, а сравниваем с `p_big[step+1]`. Абсолютные rMAE нельзя сравнивать с референс-скриптом (где метка = следующий T_big пивот). Для сравнения между T_frac значениями смещение систематическое и не искажает форму кривой.

**Scale mismatch.** При T_frac << T_big: col 1,2 запроса (≈±T_big%) являются выбросами в z-score пространстве пула (≈±T_frac%). Выбор соседей определяется почти только col 0 (ценой). Количественно виден в mean_d: растёт в 8× при T_frac=0.2% vs T_frac=4%.

**Единственный тикер.** Результаты получены на SBER. Обобщение на другие тикеры не проверено.

## 7. Анализ и выводы

**Г1 подтверждена:** frac-only пул работает — при правильном T_frac rMAE < baseline.

**Г2 подтверждена:** оптимальное T_frac ≈ 0.85 × T_big (ratio ~1.4–1.7×). Паттерн воспроизведён на двух значениях T_big.

**Г3 подтверждена:** при малых T_frac mean_d растёт в 5–8 раз, rMAE на 30–50% хуже baseline. Переход «хуже → лучше» происходит резко около T_frac/T_big ≈ 0.65.

**Концептуальный вывод:** оптимум не в «7× ratio» (T_frac ≈ T_big/7), а в «чуть меньше T_big» (ratio ~1.5×). Это объясняется тем, что фрактальная структура использует самоподобие ближайшего масштаба: T_frac ≈ T_big даёт почти идентичное embedding-пространство, но чуть больше точек. При T_frac << T_big embedding-пространства разные, scale mismatch необратим.

**Связь с предыдущими результатами:** референс `zigzag_forecast_ref.py` использует T_frac=0.6% (ratio ~29–8×) как часть КОМБИНИРОВАННОГО пула (T_big + T_frac). Там мелкие события дополняют крупные. В режиме frac-only T/7 не работает — нужен T×0.85.

## 8. Дальнейшие направления

1. **Смешанный пул T_big + T_frac(0.85×):** сравнить с frac-only и чистым T_big baseline
2. **Оптимум T_frac для ансамбля:** переоптимизировать T_small в референс-скрипте под новое правило
3. **Многоуровневость:** T_big ← T_frac ← T_frac² (цепочка предсказаний снизу вверх)
4. **Другие тикеры:** проверить GAZP, LKOH, GMKN — универсально ли T_frac ≈ 0.85 × T_big?
5. **Метка y = следующий T_big пивот:** альтернативная постановка без смещения метки
6. **p > 3:** при T_frac ≈ T_big масштабы embedding совместимы → возможно p=4..6 несёт дополнительный сигнал
