# 24 — Logtrend-стационаризация на крупном масштабе ("контрольный тест")

## 1. Гипотезы

- Пользователь явно ожидал отрицательный результат ("думаю это всё
  сломает... контрольный тест"): logtrend-стационаризация
  (`ratio = close/exp(trend)`, Direction A, CLAUDE.md "Ключевые
  методические решения") никогда не применялась к зигзагу на КРУПНОМ
  масштабе (T_big~20%, Direction B) — проверяем, ломает ли она результат,
  как ожидалось, или нет.
- Проверяются ОБА варианта построения зигзага на detrended-ряду:
  symmetric (стандарт) и asymmetric (эксп.23, percentage-symmetric) —
  сохраняется ли найденное в эксп.23 улучшение при переходе на
  стационаризованный ряд.

## 2. Концепции, терминология, обозначения

- **logtrend (causal OLS)** — `trend[t] = a + b·t`, подгонка МНК на
  `log(close[:t+1])`, инкрементальные суммы O(N), без разогрева (копия
  `research/phase3_filterbank/41_linear_trend_norm.py::lintrend_causal`,
  применена к log(close), не заново к close).
- **detrended high/low** — `log(high)−trend`, `log(low)−trend` (единый
  тренд, посчитанный по close, вычитается из обеих полос).
- Четыре условия: raw+symmetric (эталон 17f), raw+asymmetric (эксп.23),
  logtrend+symmetric, logtrend+asymmetric (два последних — считаются здесь).

## 3. Методология и протокол

SBER, D_allpeers. Тот же протокол, что эксп.21/23: подбор T_big (для
symmetric) / P_pct (для asymmetric) под число пивотов, сопоставимое с
эталоном (73, raw+symmetric@T_big=20%), независимая калибровка (m,θ,T_ratio)
для каждого нового условия. Пиры проходят ТУ ЖЕ детрендизацию (свой
собственный causal-тренд на своём log(close)).

## 4. Параметры

```
TBIG_SEARCH_GRID=[0.03..0.30] шаг 0.005 (шире вниз, т.к. detrended ряд
  может требовать другой масштаб), N_TARGET=73 пивота
PPCT_SEARCH_GRID — та же сетка, что эксп.23
M_GRID=[2,3,4,5], THETA∈[0,32], T_ratio∈[0.50,0.95]
```

## 5. Критика постановки

- Только SBER, только "контрольный" прогон (не многотикерная проверка) —
  соответствует духу запроса ("контрольный тест", ожидание отрицательного
  результата, не претензия на новый стандарт).
- Число пивотов после детрендинга изменилось незначительно (74/69 против
  целевых 73) — сам тренд, судя по всему, слишком "медленный" компонент
  относительно масштаба T_big~20%, чтобы сильно сдвинуть структуру
  зигзага (в отличие от SSA в эксп.21, которая резко сократила пул).

## 7. Анализ и выводы

- **Ожидание пользователя подтвердилось**: logtrend-детрендинг ухудшает
  результат на крупном масштабе — logtrend+symmetric хуже raw+symmetric
  на +1.8% (0.6049→0.6157), logtrend+asymmetric хуже raw+asymmetric на
  +4.9% (0.5900→0.6188).
- **Важный побочный эффект**: на detrended-ряду асимметричная поправка
  (эксп.23) ПЕРЕСТАЁТ помогать — logtrend+asymmetric (0.6188) чуть хуже
  logtrend+symmetric (0.6157), обратный знак относительно raw-серии.
  То есть выигрыш от percentage-symmetric порога специфичен для сырого
  ряда, не универсален относительно препроцессинга.
- **Содержательное объяснение**: тот же паттерн, что в эксп.21 (SSA) —
  попытка "очистить" ряд перед КРУПНОМАСШТАБНЫМ зигзагом вредит, потому
  что часть того, что зигзаг на этом масштабе ловит как "разворот",
  физически связана с самим долгосрочным трендом (или его сменой) —
  вычитание тренда убирает содержательный сигнал вместе с "шумом".
  Согласуется с общим выводом сессии: "чистого шума" на бирже, похоже,
  нет — то, что выглядит как шум/тренд для одной цели (Direction A,
  тонкая структура att), для другой цели (Direction B, крупные события)
  может быть частью самого сигнала.

## 8. Дальнейшие направления

- Ветка "препроцессинг перед крупномасштабным зигзагом" (SSA — эксп.21,
  logtrend — эксп.24) закрыта дважды отрицательным результатом — не
  тратить время на дальнейшие варианты сглаживания/стационаризации без
  нового веского аргумента.
- Открытый вопрос: сохраняется ли `asymmetric > symmetric` только на
  СЫРОМ ряду специфично, или это зависит от чего-то ещё (масштаба T,
  тикера) — уже отдельно исследуется в эксп.23 (многотикерная проверка).
