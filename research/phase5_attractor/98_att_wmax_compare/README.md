## 1. Гипотезы

**H1 (W_max / Theiler-окно):** Temporal locality bias — главная причина неустойчивости прогноза:
при маленьком Theiler-окне KNN возвращает 50 ближайших баров из недавнего прошлого, которые
разделяют большинство координат вложения с запросом → LP-очистка пула работает «на себе»,
d_local занижен. При большом W пул становится исторически разнообразным, LP видит реальную
топологию аттрактора → d_local стабилен, ACF остатков обнуляется.

**H2 (Такенс-driven p_fit):** Теоретически минимальный p_fit = 2·d_local + 1. Если
d_local определяется через LP-очистку локального пула соседей (а не через глобальные
оценщики), это замкнутый алгоритм без ручного подбора p.

**H3 (LP-коррекция шага):** Проецирование каждого рекурсивного LWR-предсказания обратно
на d_local-мерное многообразие аттрактора (используя LP-очищенный пул) сдерживает
loopback-дрейф прогноза.

**H4 (att как начальный шумодав):** Применение глобального LP-фильтра (m=9, d=3, k=30, n=3)
к ratio перед W_max-поиском упростит оценку d_local — att уже гладкий, пул att-окон будет
ближе к реальному многообразию, LP-очистка пула быстрее сойдётся.

## 3. Методология и протокол

### Шаг 1 — Предобработка (метод A и B)

```
ratio → каузальный LP-фильтр (m=9, d=3, k=30, n=3) → att
```

**Каузальный LP-фильтр:** для точки t используем только delay-векторы, заканчивающиеся
строго до t. Не допускает утечки будущего в att[t]. Реализован итерационно (n_iter=3).

### Шаг 2 — Поиск W_max (только метод A)

Сканируем W ∈ {9, 13, ..., 61} (шаг 4):

1. `build_pool(att, t_orig, P=64, K=50, W)` → 50 ближайших в 64D из прошлого с Theiler W
2. `svd_d_local(X_pool)` → `d_before`
3. `lp_clean(X_pool, d_before, K'=10, n=20)` → `X_clean`
4. `svd_d_local(X_clean)` → `d_after`
5. `acf1_ok(X_pool, X_clean, d_after)` → ok = |signed mean ACF lag-1| ≤ CI95

W_max = наибольшее W с ok=True. d_local = d_after при W_max.

Если W_max не найден — origin отбрасывается (нет надёжного прогноза).

### Шаг 3 — Прогноз (метод A / B / C)

```
p_fit = 2·d_local + 2
ξ = 3·(p_fit+1) + 5
X_raw = att[pool_times, -p_fit:]   # K × p_fit срезы из пула
Y_raw = att[pool_times + 1]        # следующие значения
```

Рефайн в p_fit-пространстве → ξ ближайших → рекурсивный LWR(acc_ang) H=10 шагов.

Метод A: после каждого шага LP-коррекция через `X_clean[:, -p_fit:]` (K_CORR=10, d=d_local).

### Промежуточный этап (lp_wmax_visual.py)

Тот же алгоритм, но на сыром `ratio` (а не на `att`). Включал три вариanta MARGIN ∈ {1, 2, 3}
и сравнение без LP-коррекции vs с LP-коррекцией. 5 origins, SBER 1d.

## 5. Критика постановки

### Каузальность att

Глобальный LP-фильтр реализован каузально: att[t] использует только delay-векторы
из t' < t. Это корректно для walk-forward. Первые m·k баров (≈270) плохо инициализированы
из-за недостатка истории — на практике не задействованы (origins > 4000).

### ACF-критерий не откалиброван под att

ACF-критерий разрабатывался для ratio (сырого). att уже сглаженный — LP-очистка att-пула
может «перечистить» его (схлопнуть в 1-2 измерения), и остатки приобретают нестандартное
распределение ACF. Критерий может давать ложные отказы.

### Некаузальный att в lp_wmax_visual.py

Первая версия скрипта (lp_wmax_visual.py) работала на ratio, не att → H4 не применима.
В 98_att_wmax_compare.py добавлен каузальный LP. Разница в качестве att ещё не измерена.

### Один тикер, визуальная оценка

5 origins SBER — только демонстрация концепции. Количественное сравнение с baseline
(ensemble aligned, −12.41%) требует walk-forward на 8 тикерах × 40 origins.

### MARGIN = 2 фиксирован

Из lp_wmax_visual.py видно, что три варианта MARGIN ведут похоже. Выбрали средний (2).
Не является критичным параметром.

## 7. Анализ и выводы

### H1 (Theiler-окно) — ПОДТВЕРЖДЕНА на ratio

На ratio 4/5 origins: W_max=61. При малых W пул состоит из ~50 последних баров,
которые разделяют координаты вложения с запросом → LP-очистка сдвигает все точки
к одному центроиду, d_after занижен, ACF остатков велик. При W=61 пул исторически
разнообразен, LP видит реальную топологию, d_after стабильно 3-4.

Вывод для ratio: Theiler-окно работает и ACF-критерий разумен.

### H1 на att — ПРОВАЛЕНА (метод A)

При переходе к att ACF-критерий отказывает в 4/5 origins. Причина: att уже гладкий,
LP-очистка att-пула "перегибает" — схлопывает в 1-2 измерения, остатки ≠ белый шум
не из-за структуры аттрактора, а из-за over-projection на слишком малый d_eff.
Критерий требует доработки для гладких сигналов.

### H2 (Такенс p_fit) — ЧАСТИЧНО ПОДТВЕРЖДЕНА

d_local = 3-4 (ratio) или 3-6 (att) → p_fit = 8-14 — попадает в стандартный диапазон
[4..16], но адаптивно. В lp_wmax_visual.py прогнозы выглядят разумно при Takens p.

Однако: без walk-forward нельзя утверждать, что это лучше ensemble (−12.41%).

### H3 (LP-коррекция) — ПОДТВЕРЖДЕНА визуально

Строка «с LP-коррекцией» на lp_wmax_forecast.png визуально лучше во всех 5 origins.
Loopback на 2025-03-10 присутствует даже с коррекцией, но менее выражен.

### H4 (att как шумодав) — НЕ УЛУЧШИЛА A, метод B рабочий

Глобальный LP не помог ACF-критерию (A). Зато метод B (SVD без ACF) на att всегда
даёт разумный d_local и p_fit. Это означает, что att + SVD-оценка размерности —
перспективный путь к адаптивному p без сложного ACF-теста.

### Ключевой вывод сессии

Концепция «W_max → d_local → Такенс p_fit» работает на ratio (lp_wmax_visual.py).
Переход к att как шумодаву оправдан, но ACF-критерий нужно адаптировать.
Самый простой путь вперёд: **att → SVD пула (без LP-очистки) → d_local → p_fit → LWR + LP corr**.
Это метод B, и он всегда работает.

## 8. Дальнейшие направления

### Приоритет 1: Walk-forward сравнение

Метод B (att + SVD-d_local + p_fit) vs ensemble aligned (−12.41%). Протокол: 8 тикеров 1d,
40 origins × шаг 5, H=1, rMAE. Если B выигрывает — новый стандарт. Если нет — понять почему.

### Приоритет 2: Починить ACF-критерий для att

Проблема: LP-очистка att-пула приводит к over-projection. Возможные решения:
- Поднять D_THRESH (0.90 вместо 0.80) — не так агрессивно схлопывать d
- Уменьшить N_LP_ITER для att-пула (он уже чище, не нужно 20 итераций)
- Использовать d_before (не d_after) как основу для ACF P_ref

### Приоритет 3: GP D₂ перепроверить

D₂ ≈ 1.098 выглядит заниженным (ожидалось 2-3 по скр.94). Возможно: узкий ε-диапазон,
недостаточный GP_M, или эффект logtrend нормализации. Перезапустить с расширенным ε.

### Приоритет 4: Loopback при H>1

На 2025-03-10 рекурсивный прогноз уходит вверх. LP-коррекция помогает, но не полностью.
Исследовать: зависит ли глубина loopback от d_local и K_CORR? Нужен ли более жёсткий
clip по att-диапазону на шаге прогноза?
