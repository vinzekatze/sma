## Скрипты фазы 5

### 81 — Глобальный acc_ang (`81_global_acc_ang.py`)

**Гипотеза:** деградация global_blend (+8.6%, скр.80) вызвана тем, что глобальные
соседи отбираются по d_pos без учёта кривизны. Применить acc_ang и к глобальному
поиску.

**Результат: отклонено.** gacc при любом blend_frac ≤ чистого acc_ang.
Оптимум — blend_frac=1.0 (нет глобальных соседей).

**Вывод:** acc_ang работает через позиционно-близкую окрестность; глобальные
соседи с похожей кривизной приходят из чужих регионов фазового пространства → LWR
получает несовместимых соседей.

### 82 — Adaptive λ + Temporal decay (`82_adaptive_lambda_temporal_decay.py`)

**Гипотеза 1 (adaptive λ):** вычислять λ = σ_pos/σ_acc локально по пулу каскада.

**Результат:** adaptive λ = −2.7% vs acc_ang fixed −10.3%. **Отклонено.**
Равновесное взвешивание (λ_adaptive >> 0.01) позволяет дальним векторам с похожей
кривизной конкурировать с ближними → хуже. acc_ang работает только как tie-breaker.

**Гипотеза 2 (temporal decay):** w_i *= exp(−α·age_i), скидка на "устаревших" соседей.

**Результат: жёстко отклонено.** Даже α=0.001 (T½≈693 бара) даёт +11.5%.
Паттерн аттрактора трёхлетней давности так же релевантен, как прошлогодний;
LWR уже дисконтирует плохих соседей через расстояние.

### 83-87 — Per-origin p_fit (`83…87_*.py`)

Серия исследует: можно ли адаптировать размерность встраивания к текущей локальной
структуре аттрактора?

#### 83 — Смещённый oracle (`83_pfit_per_origin.py`)

Каскад фиксирован (P_FIT=16), варьируется только размерность LWR-регрессии.

- Oracle (знает истину): rMAE = 0.0296 (−52.9%) — огромный потенциал!
- LOO-select: rMAE = 0.0517 (−17.6%) — **но это артефакт**: соседи отобраны
  под p=16, в p=4 они структурно ближе → LOO смещён к малым p.

**Ключевой вывод:** потолок −53% реален, oracle p_reg равномерно распределён по
сетке [4…16] → аттрактор многомасштабен, разные регионы требуют разного p.

#### 84 — Честный каскад (`84_honest_pfit_cascade.py`)

Для каждого p_reg — независимый каскад от P_MAX=64 до p_reg. Соседи честны.

- Oracle: −54.8%  (подтверждён, равномерное распределение p)
- LOO-select: **+6.7%** — стало хуже! Причина: разный xi per p_reg (xi=15 для p=4
  vs xi=51 для p=16) → несопоставимые LOO-ошибки.
- Ensemble (1/LOO): −8.95% — работает без выбора.

#### 85 — Фиксированный xi (`85_fixed_xi_pfit.py`)

Зафиксировать xi=51 для всех p_reg → сопоставимые LOO.

- LOO-select: −6.5% (теперь улучшает, но скромно)
- Ensemble: −10.0% ← лучший
- LOO vs Oracle: совпадение 15%, r=0.011 — случайный уровень

**Вывод:** LOO в принципе не может выбрать правильный p — LOO-ошибки по-прежнему
смещены к малым p (структурно меньше дисперсия у переопределённых моделей).

#### 86 — AIC-штраф (`86_aic_penalized_loo.py`)

LOO × (1 + k·(p+1)/xi) для k ∈ {0, 0.5, 1, 2, 3, 5}; AICc-поправка.

- Все варианты LOO с штрафом: −6 … −7% (плато, штраф не помогает)
- AICc: −5.9% (хуже raw)
- Чем больше k → тем больше доля p=4 (штраф гонит в неправильную сторону!)
- **Ensemble стабильно −10.0%** — лучший метод, не требует выбора.

**Вывод:** мультипликативный штраф структурно не работает. LOO как критерий выбора p
при одинаковом xi — неправильный инструмент.

#### 87 — Признаковый предиктор + z-нормировка (`87_pfit_predictor.py`)

**Гипотеза A:** локальные признаки аттрактора предсказывают oracle_p.

Признаки: кривизна, волатильность, ac4, ac16, спектральный центроид, slope_n, LOO-CV.

```
curv      r=+0.024    vol_ratio r=−0.062
ac4       r=+0.036    ac16      r=+0.068  ← лучший, незначим
spec_c    r=−0.036    slope_n   r=−0.036

Линейный предиктор R²=0.021  (≈ 0)
Совпадение с oracle: 11.6%  (случайный уровень ≈ 14%)
```

**Результат: ни один признак не коррелирует с oracle_p.** Предиктор хуже случайного.

**Гипотеза B:** z-нормировка LOO (μ/σ по исторической выборке per p_reg) убирает смещение.

- z_select: rMAE = 0.0561 (−0.4%) — распределение p ≈ oracle (4:16%, 16:21%) ✓
  но rMAE почти не меняется → знаем среднюю частоту, не знаем per-origin выбор
- z_ensemble: rMAE = 0.0522 (−7.2%)
- **Ensemble 1/LOO: −10.0%** ← остаётся лучшим

### 89 — Шаг каскада: сетка множителей (`89_cascade_step.py`)

**Гипотеза:** октавный шаг ×2 — не обязательно оптимальный. Аттрактор с
нечёткими масштабами может требовать ×√2 (полуоктавный) или ×3.

Тест: шаги ×√2, ×1.5, ×2.0, ×2.5, ×3.0, ×4.0 при P_MAX=64, P_FIT=16,
два режима: fixed_16 (p_reg=16) и ensemble (все p_reg, честный каскад).

**Результаты:**

| Шаг | Уровни (p=16) | fixed_16 Δ | ensemble Δ | oracle Δ |
|---|---|---|---|---|
| ×√2 | 64→45→31→21→16 | +15.72% | −5.12% | −45.27% |
| ×1.5 | 64→42→28→18→16 | +13.94% | −4.39% | −45.89% |
| **×2.0** | **64→32→16** | **0.00%** | **−10.01%** | **−53.23%** |
| ×2.5 | 64→25→16 | +3.72% | −7.02% | −50.10% |
| ×3.0 | 64→21→16 | +14.00% | −4.87% | −46.89% |
| ×4.0 | 64→16 | +4.22% | −7.86% | −50.97% |

**Ключевые наблюдения:**
1. Oracle ceiling тоже падает при нестандартных шагах (×√2: −45% vs ×2: −53%) —
   ×2 структурно находит лучших соседей даже при знании истины.
2. Тепловая карта: мелкие шаги (×√2, ×1.5) катастрофичны для больших p
   (p=16: +15.7%), но нейтральны для малых (p=4: −6.9%).
   Крупные шаги (×3) ломаются на средних p (p=8: +6.1%).
3. ×2 единственный шаг, дающий ровный результат по всему диапазону p.

**Вывод: ×2 — не произвольная «круглая цифра», а структурно оптимальный шаг
для этого аттрактора.** Подтверждён на 8 тикерах 1d, 2 режимах, oracle-потолке.

### 93 — P-aligned каскад (`93_aligned_cascade.py`)  ⭐ ПРОРЫВ

**Идея:** уровни каскада для p_fit = p_fit × {1, 2, 4, 8, ...} ≤ P_MAX.
Свойство вложенности: p-D ⊂ 2p-D ⊂ 4p-D → сходство на уровне 2p гарантирует
сходство в p-мерном подпространстве. Стандартный [64→32→16→p] нарушает это для
нечётных p (уровень 32 не является кратным 5, 7, 9 и т.д.).

Примеры: p=5→[40→20→10→5], p=9→[36→18→9], p=4→[64→32→16→8→4] (совпадает со std).

| Метод | rMAE | Δ | SignAcc |
|---|---|---|---|
| oracle std | 0.0242 | −57.07% | 97.8% |
| **oracle aligned** | **0.0185** | **−67.10%** | 97.5% |
| ensemble std | 0.0511 | −9.18% | 93.1% |
| **ensemble aligned** | **0.0493** | **−12.41%** | **94.1%** |
| oracle extended [P_MAX+aligned] | 0.0215 | −61.88% | 98.1% |
| ensemble extended | 0.0500 | −11.13% | 94.7% |

**Ключевые результаты:**
1. Oracle ceiling: −67.10% vs −57.07% (+10pp) — согласованный каскад находит
   значительно лучших соседей.
2. **Ensemble: −12.41% vs −9.18% — новый практический рекорд** (до этого −10.01%).
3. p=9 ожил: 3% → 10% в oracle_p распределении. Стандартный каскад занижал
   нечётные p из-за несогласованных промежуточных уровней.
4. LOO-select хуже при aligned (−0.71%): разные каскады делают LOO-ошибки
   несопоставимыми между p_reg значениями.

**Вывод: p-aligned каскад — структурное улучшение, подтверждённое теоретически
и эмпирически. Новый стандарт: полная сетка p∈[4..16] + aligned каскад + ensemble.**

### 98 — W_max + теоретически обоснованный p_fit (`98_att_wmax_compare/`)

**Ключевая идея сессии (2026-06-14):** вместо эмпирического подбора p (ensemble)
найти per-origin p через теорему Такенса: p_fit = 2·d_local + 2, где d_local —
размерность аттрактора ПОСЛЕ LP-очистки локального пула соседей.

**Theiler-окно (W):** исключает из пула соседей с |t_end − t_orig| < W → не разделяют
координаты вложения с запросом → нет temporal locality bias. W_max = наибольшее W,
где ACF (signed mean lag-1) остатков LP-очистки обнуляется.

**ACF-критерий (signed mean, не |mean|):** `CI95 = 1.96/√(K·P_ref)`, `P_ref = max(7, 2·d_after+1)`.
Ключевое: mean берётся знаковый — знаки ACF по разным строкам пула могут гасить друг друга.

**Прогноз без каскада:** W_max-пул (50 исторически разнообразных соседей) уже выполняет
роль верхнего уровня каскада. Прямой рефайн до ξ в p_fit-пространстве.

**LP-коррекция:** после каждого LWR-шага предсказанный вектор проецируется на d_local-мерное
многообразие X_clean[:, -p_fit:] (K_CORR=10). Подтверждена визуально: помогает однозначно.

| Вариант | W_max (из 5) | d_local | p_fit | LP-corr |
|---|---|---|---|---|
| lp_wmax_visual.py (ratio → W_max) | 4/5 | 3–4 | 8–10 | помогает ✓ |
| 98: метод A (att → W_max + ACF) | **1/5** | 3 | 8 | — |
| 98: метод B (att → SVD, макс. W) | 5/5 | 3–6 | 8–14 | н/д |
| 98: метод C (att → фикс. p=16) | — | — | 16 | — |

**Проблема метода A:** ACF-критерий на att-пуле слишком строг — att уже гладкий,
LP-очистка att-пула over-projects, остатки получают нестандартный ACF → 4/5 origins отказ.

**Вывод:** концепция работает на ratio. На att нужна адаптация критерия (D_THRESH↑ или
меньше итераций LP) или упрощение до метода B (SVD без очистки).

**Перспектива:** att + SVD-d_local + p_fit (метод B) vs ensemble aligned (−12.41%) —
ключевой walk-forward тест (следующий скрипт).

### 99 — Индикаторы кармана локального аттрактора (`99_pocket_indicators/`)

**Гипотеза:** области фазового пространства с хорошим прогнозом att имеют
измеримые геометрические свойства, предсказуемые до запуска LWR.

**4 индикатора:**

| Индикатор | Теоретическое ожидание |
|---|---|
| ρ(A) якобиан | < 1 → локально сжимающийся поток → хороший карман |
| d_L TwoNN | d_L << p_fit → низкоразмерный карман → хороший прогноз |
| DET RQA | высокий → детерминированная область → хороший прогноз |
| LOO-MAPE | прокси val_mape, прямая корреляция с ошибкой |

**Три режима (8 тикеров 1d, 100 origins каждый):**

| Режим | n_casc | median rMAE | ρ(A) r | d_L r | DET r | LOO-MAPE r |
|---|---|---|---|---|---|---|
| lp600 (LP_W=600) | 311 | 0.924 | +0.007 | −0.090 | +0.035 | +0.070 |
| lp2000 (LP_W=2000) | 1711 | 0.929 | +0.002 | +0.042 | +0.012 | **+0.096** |
| longhist (LP_W=600 + 3000 att_points) | 2712 | **0.905** | −0.023 | +0.073 | **+0.167** | +0.092 |

**Ключевые наблюдения:**
- **ρ(A)**: r≈0 во всех режимах → H1a отклонена.
- **d_L TwoNN**: знак нестабилен между режимами → H1b не подтверждена.
- **DET в longhist**: r=+0.167 (7/8 тикеров) — но знак обратный теоретическому:
  высокий DET → хуже прогноз. Объяснение: высокая рекуррентность означает что
  50 соседей почти идентичны → LWR вырождается из-за нехватки вариабельности.
- **LOO-MAPE**: единственный стабильно-воспроизводимый индикатор (7/8 тикеров
  положительны в lp600 и lp2000), но r слабый (≈0.09).

**Основная проблема малого сигнала:** att_actual[t+h] и att_forecast строятся
из разных LP-прогонов (разные скользящие окна) → шум в целевой переменной.

#### Поэтапный LP с убывающим d

Идея: вместо LP(d=3, n=3) применять LP(d=15) → LP(d=10) → LP(d=6) → LP(d=3),
постепенно сжимая сигнал на аттрактор.

| Схема | d_L(9D) | smoothness | rMAE |
|---|---|---|---|
| **standard LP(d=3, n=3)** | 4.98 | **0.000867** | **лучший** |
| cascade 15→8→4→3 | 4.71 | 0.001030 | хуже |
| cascade 15→10→6→3 | 7.75 | 0.001086 | хуже |
| cascade 15→3 (2 шага) | 8.31 | 0.001675 | хуже |

**Вывод:** стандартный LP(n=3) выигрывает по гладкости и качеству прогноза.
Предварительный проход с большим d оставляет след который финальный d=3 не убирает.
LP(n=3) уже является оптимальной итерационной схемой.

### Главный методологический вывод

**Аттрактор нельзя «поймать» заранее через теорию динамического хаоса.**

Все попытки охарактеризовать качество кармана до прогноза дали противоречивые
или нулевые результаты:
- TwoNN: d_L не предсказывает качество прогноза (нестабильный знак, r≈0)
- DET: обратный знак в longhist-режиме
- ρ(A): r≈0 во всех режимах
- LP с переменным m или убывающим d: не улучшает стандартный LP

Причина, вероятно, в том, что «аттрактор» в att — это режимозависимый объект:
когда рынок структурирован (тренд/осцилляция), LP его ловит; когда рынок шумит —
LP создаёт гладкий, но содержательно пустой сигнал. Отличить эти два случая
до получения результата прогноза геометрическими методами не удаётся.

**Единственный работающий post-hoc индикатор:** val_mape (r=0.51, фаза 1) —
но он требует отдельного LWR-прогона на исторические данные.

### Переход к фазе 6

**Текущий лучший пайплайн:**
```
close → logtrend → ratio → LP(m=9,d=3,k=30,n=3) → att
  → p-aligned октавный каскад (P_MAX=288, p∈[4..16])
  → LWR + acc_ang (λ=0.01) + LP-коррекция (n=1)
  → ensemble 1/LOO → прогноз att
```
Результат: **−12.41% rMAE** vs naive_last.

**Открытый резерв:** oracle потолок −67.1% → практическое улучшение достигает лишь
−12.41% → огромный gap. Per-origin p_fit — главная нерешённая задача.

**Фаза 6 — эмпирические методы улучшения прогноза:**
- Per-origin p_fit без LOO (новые подходы)
- Noise-компонента (GARCH или иное)
- Оптимизация LP_W
- Возможно: val_mape как pre-hoc gate через быстрый backward LWR
