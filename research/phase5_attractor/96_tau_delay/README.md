## 1. Гипотезы

**H1:** При τ>1 мультиколлинеарность матрицы LWR снижается → oracle_p концентрируется в меньшем диапазоне (перестаёт быть Uniform[2..80]).

**H2:** Оптимальный физический масштаб (oracle_bars = oracle_p × τ) одинаков при разных τ. Если да — τ и p_reg взаимозаменяемы, и система «видит» один и тот же масштаб разными путями.

**H3:** При τ=3 лучший средний rMAE(p, τ=3) ниже лучшего rMAE(p, τ=1). Снижение мультиколлинеарности улучшает регрессию.

**H4:** Оптимальный τ согласован с LP-фильтром: τ_opt ≈ m/d = 9/3 = 3 (шаг между «независимыми» проекциями).

## 2. Концепции, терминология, обозначения

| Обозначение | Расшифровка |
|---|---|
| **τ (тау)** | Задержка embedding: вместо att[t], att[t-1], ..., att[t-p+1] берём att[t], att[t-τ], att[t-2τ], ..., att[t-(p-1)τ] |
| **τ=1** | Стандарт 95a — последовательные значения |
| **p_reg** | Число координат вектора признаков (как раньше). Физическая история = (p−1)·τ+1 ≈ p·τ баров |
| **физ. диапазон** | Окно в барах ≤80. p_max(τ) = 80÷τ |
| **oracle_p** | Лучший p_reg по |pred−true| для данного τ |
| **oracle_bars** | oracle_p × τ — физическое расстояние в барах; позволяет сравнивать τ |
| **acc_τ[t]** | τ-задержанное ускорение: att[t] − 2·att[t−τ] + att[t−2τ] |
| **cols(p,τ)** | Индексы столбцов X_full для τ-delayed embedding: [P_MAX-1, P_MAX-1-τ, ..., P_MAX-1-(p-1)τ] |
| **cascade(p,τ)** | p-aligned каскад с τ-задержанными расстояниями; expansion = (p_lvl−p_next)·τ баров |
| **rMAE(p,τ)** | mean(|pred−true|)/std(att) при данном (p, τ) |
| **мультиколлинеарность** | Высокая корреляция соседних столбцов матрицы LWR. При τ=1 и гладком att: r(att[t], att[t-1]) ≈ 0.9+. При τ=3: r(att[t], att[t-3]) ≪ 0.9 |

## 3. Методология и протокол

### 3.1 Walk-forward
Те же 200 origins, что в 95b (stride=2 из 95a, t_orig ∈ [2328..4318]).

Для каждого τ:
1. Вычислить acc_τ[t] = att[t] − 2·att[t−τ] + att[t−2τ] на полном ряду
2. Построить _Ctx: X_full (N_lib × P_MAX), X_acc (N_lib × P_MAX из acc_τ)
3. Для каждого p ∈ p_grid(τ): τ-delayed forecast
4. Записать JSONL

### 3.2 τ-delayed cascade
- Уровни: p_reg × {1, 2, 4, ...} ≤ p_max_τ = (P_MAX−1)÷τ+1
- Расстояние на уровне p_lvl: L2 в cols(p_lvl, τ)-пространстве
- Временно́е расширение: (p_lvl − p_next) × τ баров (физический масштаб)

### 3.3 Acc_ang
acc_ang = d_pos + λ·d_ang, где d_ang — косинусное расстояние acc_τ-векторов (тот же набор cols(p_reg, τ)).

## 5. Критика постановки

**5.1 λ=0.01 не перекалиброван под τ.**
acc_τ при τ=3 имеет другой диапазон значений, чем acc_1. d_ang может быть систематически завышен или занижен. Фиксируем λ=0.01, результат интерпретируем с оговоркой.

**5.2 Каскад при τ>1 менее глубокий.**
p_max_τ(τ=3) ≈ 100, уровней каскада у малых p_reg: 1–2 (вместо 4–6 при τ=1). Меньше уровней → хуже фильтрация соседей → возможная деградация не из-за τ, а из-за каскада.

**5.3 Расширение radius × τ может создавать большие candidate sets.**
При τ=3, p_reg=27, первый переход 54→27: expansion = 27×3 = 81 баров × ξ≈89 кандидатов = 7K+ точек до unique. Нагрузка управляемая, но медленнее τ=1.

**5.4 oracle_p несопоставим между τ напрямую.**
oracle_p=10 при τ=1 (10 баров) ≠ oracle_p=10 при τ=3 (30 баров). Для межτ сравнения используем oracle_bars.

**5.5 Автокорреляция att при τ=3 может быть ещё высокой.**
Если LP создаёт att с характерным временем 27 баров, то r(att[t], att[t-3]) ≈ 0.85 — мультиколлинеарность снижается, но не устраняется. τ=9 (= m·n/d?) мог бы дать более независимые координаты, но выходит за рамки разумного p_reg.

## 7. Анализ и выводы

### H1 — ЧАСТИЧНО ПОДТВЕРЖДЕНА (по форме, отклонена по смыслу)

oracle_p формально сжимается с τ (std: 22.9 → 12.0 → 7.3). Однако это **артефакт p_max(τ) = 80÷τ**, а не реальная концентрация вокруг оптимума: диапазон oracle_p обрезается сверху. Мультиколлинеарность снижается, но это не приводит к улучшению рMAE.

### H2 — ПОДТВЕРЖДЕНА ⭐

**oracle_bars = oracle_p × τ ≈ 33-37 bars стабильно для всех τ.**  
Медиана: τ=1: 29 bars, τ=2: 36 bars, τ=3: 36 bars. Разброс (~25%) высокий, но среднее устойчиво.  
Вывод: аттрактор att имеет **характерный масштаб ~33-37 баров**. τ и p_reg — взаимозаменяемые ручки для доступа к этому масштабу, но τ=1 позволяет это делать без потерь.

### H3 — ОТКЛОНЕНА

τ=1 доминирует во всех метриках абсолютного rMAE:
- best_p rMAE: τ=1: **0.228** < τ=2: 0.290 < τ=3: 0.293
- ensemble rMAE: τ=1: **0.218** < τ=2: 0.262 < τ=3: 0.302

Снижение мультиколлинеарности (τ>1) не компенсирует потерю информации от skip-sampling и укорочения каскада.

### H4 — ОТКЛОНЕНА

τ_opt = 1 (наименьший тестированный). τ=3 (= m/d = 9/3) не выделяется.

### Главное открытие: oracle_bars ≈ 35 → оптимальный p при τ=1 ≈ 33-37, не 16

Текущий дефолт p_fit=16 соответствует физическому масштабу 16 баров. oracle_bars показывает, что оптимальный масштаб в ~2 раза больше — около 33-37 баров. При τ=1 это означает p_reg ≈ 33-37.  
Глобальный d̂_LB≈7 (95b) → p_Takens=15 был самосогласованным лишь при p_search=20; при p_search=35 d̂_LB≈9 → p_Takens=19. Истинная рекомендация: **p_fit ≈ 30-40**.

### Аномалия τ=3: best_p=2

При τ=3 лучший p=2 (два skip-sampling шага: att[t] и att[t-3]). Любое увеличение p только ухудшает результат. Вероятная причина: LP создаёт att с характерным временем ≈27 баров → att[t] и att[t-3] слабо коррелированы → уже двух точек достаточно для описания локальной геометрии. Добавление att[t-6], att[t-9] не несёт новой информации и увеличивает шум из-за расширения ξ.

## 8. Дальнейшие направления

### 8.1 oracle_bars ≠ оптимальный фиксированный p (важное уточнение)

Прямая проверка из данных 96a (τ=1):

| p | rMAE |
|---|---|
| 3 | **0.2279** ← лучший фиксированный |
| 16 | 0.2458 |
| 35 | 0.2786 ← хуже p=16! |
| 80 | 0.3119 |

oracle_bars ≈ 33 **не означает**, что p=35 лучше p=3. Кривая rMAE(p) монотонно растёт от p=3 вверх (с небольшими осцилляциями). Фиксированный p=35 хуже p=16.

Интерпретация: oracle_bars ≈ 33 описывает **масштаб аттрактора** (LP покрывает ~27-40 баров), но для регрессора оптимален малый p (меньше соседей → меньше дисперсия). Oracle с p=33 «выигрывает» по-разному для каждого origin (иногда большой p случайно попадает точнее), но фиксированный большой p проигрывает из-за разброса.

Следствие: задача — не выбрать правильный фиксированный p, а **выбирать p per-origin**. Ensemble/LOO (rMAE=0.2176) частично это делает и уже лучше любого фиксированного p.

### 8.2 LP filter bank: локальная адаптация LP под область

Вместо глобальных (m=9, d=3, k=30, n=3) — два-три варианта с разными d (1, 3, 5) и выбор по локальному критерию. Мотивация: oracle_bars имеет std≈22-24 bars (коэффициент вариации ~65%) — разброс слишком велик для фиксированного p. LP с меньшим d даёт более «резкий» att, с большим d — более «гладкий».

### 8.3 Сравнить τ=1, p=35 vs τ=3, p=12 на честной общей оси

Оба покрывают ~35 физических баров. После фиксации физического масштаба разница в rMAE покажет чистый эффект мультиколлинеарности.

### 8.4 Исследовать p_reg-adaptive прогноз без oracle

Раз oracle_bars устойчив (~35 bars), можно задать p_reg = round(35) = 35 как фиксированный параметр. Альтернативно — адаптировать p через оценку локальной автокорреляции att: lag_at_which_acf(att, tau) < 0.5 → определяет p_reg онлайн.

### 8.5 Глобальная перекалибровка ξ при p=35

ξ(p=35) = 3·36+5 = 113 соседей. Пул каскада при p=35, τ=1: P_MAX=300 → уровни [280, 140, 70, 35] — 4 уровня. Нужно проверить, что N_lib=4500+ хватает при ξ=113.
