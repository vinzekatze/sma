# 22. PE-delay как мягкий вес (soft kernel)

**Тикер/интервал**: SBER 1d | **p=5**, **ξ=18**, **val_h=10**

## Метод

Вместо hard topk-фильтра: мультипликативный PE-вес поверх LWR-веса.
Ξ соседей отбираются стандартно по d_x. Итоговый вес:

    w_combined[i] = w_lwr[i] * exp(-α * (d_pe[i] / h_pe)²)

## Результаты

| Конфиг | MAPE med | vs baseline |
|---|---|---|
| baseline (α=0) | 0.01306 | — |
| m_pe=20, α=0.25 | **0.01263** | -3.25% |
| m_pe=20, α=0.50 | 0.01265 | -3.14% |
| m_pe=20, α=1.00 | 0.01324 | +1.41% |
| m_pe=20, α=2.00 | 0.01379 | +5.59% |
| m_pe=5, α=0.25 | 0.01360 | +4.13% |
| m_pe=5, α=2.00 | 0.01468 | +12.47% |

Wilcoxon для лучшего: p=0.64 — **незначимо**.

## Выводы

1. **m_pe=20 лучше m_pe=5** — нужна более широкая история PE для сигнала
2. **Малый α (0.25) лучше** — PE-сигнал слабый, сильное взвешивание вредит
3. **Улучшение есть (-3.25%), но статистически незначимо при p=5**
4. **d_k не меняется** — отбор соседей не затронут, только веса

## Гипотеза

При p=5 PE-delay вектор длиной 5 или 20 несёт слабый сигнал,
потому что PE_WIN=50 создаёт высокую автокорреляцию.
При больших p (40-60) вектор покрывает больший временной диапазон
→ больше вариативности в PE → более сильный сигнал.
