# T04 — Полная диагностика каскада (один origin)

## 1. Гипотезы

- **H1:** Структура пула соседей принципиально меняется от уровня к уровню каскада: на верхних уровнях (большое p) пул охватывает широкую геометрически разнообразную область; на нижних (малое p = p_fit) концентрируется в локальном кластере.
- **H2:** Финальный пул LWR формируется преимущественно из «ядра» — кандидатов, отобранных уже на первом уровне clip, а не из экспансий (временны́х сдвигов).
- **H3:** Снижение LB (Levina-Bickel) от уровня к уровню отражает реальное уплощение многообразия при сужении пула, а не артефакт уменьшения числа точек.
- **H4:** Оптимальное по abs_error значение d соответствует минимальному d при котором выполняется условие d≥LB_before_q на финальном уровне.

## 2. Концепции, терминология, обозначения

- **origin = 4772** — лучший origin для SBER по среднему abs_error в exp101 (date: 2026-04-07, close=317.87).
- **d** — размерность LP-фильтра. Определяет всё: m=3d (размер окна LP), k_lp=10d (соседей LP), p_fit=m=3d (размерность вектора задержек LWR), p_max=p_fit×8 (верхний уровень каскада), xi_lwr=3(p_fit+1)+5 (размер финального пула LWR).
- **n_iter** — число итераций LP-фильтра при вычислении att.
- **Итерация** — одна комбинация (n_iter, d) из сетки. Всего 45 итераций.
- **p-aligned каскад ×2** — уровни [p_max, p_max/2, p_max/4, p_fit]. На каждом уровне: clip (отбор top-xi_lwr по расстоянию при данном p) → expand (генерация временны́х сдвигов каждого отобранного кандидата).
- **cands_entering** — индексы строк X_full, входящие на данный уровень.
- **cands_after_clip** — после отбора top-xi_lwr по L2-расстоянию в p_lvl-D.
- **cands_after_expand** — после генерации сдвигов: каждый из cands_after_clip порождает до (p_lvl - p_next) новых индексов.
- **LB (Levina-Bickel)** — оценка локальной внутренней размерности. Вычисляется для запроса (lb_q) и среднего по пулу (lb_n), до и после LP-очистки (lp_clean_set).
- **Ядро (core)** — финальные кандидаты, которые присутствовали в cands_after_clip уже на уровне 1.
- **Экспансия** — финальные кандидаты, попавшие в пул впервые через expand на уровнях 2, 3 или 4.
- **d≥LB gate** — условие надёжности из exp101: d ≥ lb_before_q на финальном уровне.

## 3. Методология

Для каждой из 45 комбинаций (n_iter, d):

1. Вычисляется att для close[:origin+1] (без утечки).
2. Строится полная матрица задержек X_full при p_top=levels[0].
3. Запускается каскад: 4 уровня, на каждом:
   - Сохраняется cands_entering (до clip), cands_after_clip, cands_after_expand.
   - Вычисляются расстояния всего входящего пула до запроса.
   - Снимается LB-диагностика (до/после lp_clean_set).
4. Выполняется LWR-прогноз на финальном пуле.
5. Анализируется выживаемость: откуда пришли финальные кандидаты.
6. Строятся фигуры и сохраняется JSON с метриками (без матриц векторов).

## 5. Критика постановки

**C1. Один origin — это разовый взгляд на динамику, а не статистика.**
Цель — понять механизм, а не измерить средние. Выбран лучший origin (min avg abs_error) чтобы видеть «идеальный» сценарий работы каскада.

**C2. LP-фильтр офлайн на close[:origin+1].**
LP-фильтр внутри функции lp_proj_signal видит всю историю до origin включительно (не каузален внутри окна, но ограничен сверху origin). Это соответствует реальному использованию в app3.

**C3. LB с K_LB_MAX=8 — потолок диагностики.**
При K_LB_MAX=8 LB не превышает ~6-7 независимо от истинной размерности. Для d>8 LB насыщается. Это известный артефакт из exp101.

**C4. PCA для фона уровня 1 — линейная проекция.**
При p_top=480 (d=20) PCA показывает линейную структуру. Нелинейные зависимости не видны. Для after_clip пула (107 точек) используется UMAP — нелинейная.

**C5. Expand порождает корреляции внутри пула.**
После expand на уровне L, в cands_after_expand входят временны́е сдвиги друг друга. На следующем уровне они конкурируют как независимые, хотя на самом деле коррелированы. Это встроенная структура каскада, не баг.

## 7. Анализ и выводы

Проведено два прогона: origin=4772 (лучший по exp101) и origin=4657 (худший).  
Дополнительно выполнен анализ топологических метрик LP-clean на каждом уровне каскада (скрипт `/tmp/cascade_topology_full.py`).

### 7.1 Структура пула и выживаемость (оба origin)

**H1 подтверждена частично.** Пул на L1 действительно шире: xi_lwr кандидатов из ~4500, в высоком p_max-мерном пространстве. Финальный L4 содержит тех же xi_lwr кандидатов, но уже отсеянных через expand+clip. Геометрически однороднее, но не «компактный кластер» в привычном смысле — временны́е кластеры сохраняются.

**H2 опровергнута.** «Ядро» (кандидаты из L1 clip, дожившие до L4) составляет 25–40% финального пула. 60–75% приходят через expand. Expand не случаен: он добавляет временно́е окружение ядра (соседние по времени бары), а не произвольные точки.

**H3 подтверждена.** LB снижается L1→L4 как структурно (пул сужается, геометрия однороднее), так и через действие LP-clean. Скачок LB на L3 (expand «загрязняет» пул) всегда восстанавливается clip на L4.

**H4 опровергнута.** Нет монотонной связи между «d ≥ LB_before_q L4» и abs_error.

### 7.3 Топологические метрики LP-clean (L1–L4)

**Метрики:** rank_corr (ρ попарных расстояний до/после LP), stress, nn5_overlap, q_shift (сдвиг запроса/медиана расстояний), rank_q.

**Наблюдение 1 — rank_corr монотонно растёт L1→L4 у всех итераций.**  
L1: 0.1–0.91 → L4: 0.86–1.00. Это конструктивное свойство каскада (пул сужается, пространство уменьшается), не предсказатель качества.

**Наблюдение 2 — rank_corr L4 не различает хорошие и плохие прогнозы.**  
4772: ρ=−0.12, p=0.42. 4657: ρ=−0.37, p=0.013, но полностью объясняется группой d=1–2. Примеры: n1d14 (err=0.021) имеет rank_corr L4=0.99; n1d15 (err=0.022) — тоже 0.99. Отличная топология, катастрофический прогноз.

**Наблюдение 3 — q_shift единственная метрика с частичным сигналом.**  
Корреляции q_shift с log(abs_error):

|  | 4772 | 4657 |
|---|---|---|
| L1 | ρ=+0.26, p=0.09 | ρ=+0.39, p=0.007 |
| L3 | ρ=+0.06 | ρ=+0.40, p=0.006 |
| L4 | ρ=+0.13 | ρ=+0.42, p=0.004 |

На 4772 — нет сигнала. На 4657 — есть, но объясняется d=1–2 группой.

**Наблюдение 4 — два типа отказа с разной топологической сигнатурой.**

**Тип A — «деградация пространства»** (d=1–2, p_fit=3–6):
- q_shift > 0.7 на всех уровнях L1–L4 («зависание»; n3d1: 0.82/0.80/0.79/0.84)
- rank_corr L4 = 0.64–0.67 (ниже нормы ~0.97+)
- LP не стабилизирует запрос — p_fit слишком мал
- **Детектируется:** q_shift L4 > 0.6

**Тип B — «нет аналогов»** (d=6–20):
- q_shift снижается к L4 до 0.1–0.4 (нормально)
- rank_corr L4 = 0.97–1.00 (LP работает)
- Но аналоги не несут предсказательного сигнала об этом att-паттерне
- **Не детектируется** топологическими метриками

**Наблюдение 5 — L1 нестабилен и не является предсказательным уровнем.**  
Ни один кандидат не присутствует в L1 clip всех 45 итераций. Перекрытие L1 clip между лучшими итерациями: 0–11% (4657), 0–7.6% (4772). Корреляции всех L1-метрик с abs_error: |ρ| < 0.26, p > 0.07. L1 — грубый входной фильтр, не качественный отбор.

---

### 7.4 Роль уровней каскада

| Уровень | Функция |
|---|---|
| L1 | Грубый отбор: из ~4500 → xi_lwr кандидатов по сырому L2 в p_max-D |
| L2–L3 | Expand: добавляет временно́е окружение (исторические «эпохи»); clip: убирает геометрически далёкие |
| L4 | Финальный пул: LP-clean и LWR работают уже на стабильной геометрии |

Expand на L3 всегда вызывает скачок LB (до ~9.85 для 4772 n1d6); следующий clip L4 его восстанавливает. Паттерн «expand загрязняет, clip очищает» устойчив.

## 8. Дальнейшие направления и гипотезы

**Г1:** Топологические метрики LP-clean на L1–L3 не несут информации о качестве прогноза.  
→ Проверить на ≥10 origins: если ρ < 0.2 везде — L1–L3 топология не используется для адаптации d.

**Г2:** q_shift L4 > 0.6 — необходимый (не достаточный) признак отказа Типа A (p_fit слишком мал).  
→ Порог и точность проверить на ≥10 origins.

**Г3:** Тип B («нет аналогов») не детектируется топологическими метриками; нужен анализ Y-значений соседей.  
→ Следующий шаг: дисперсия Y, знаковый консенсус, энтропия Y-распределения финального пула.

**Г4 (приоритетная):** Overlap финальных L4-пулов между итерациями — маркер «прогнозируемости» origin.  
→ Высокий overlap → устойчивый аттрактор → предсказуемый origin. Вычислить для 10+ origins, сравнить с rMAE.

**Г5:** Стабильное снижение q_shift к L4 — косвенный маркер регулярности аттрактора в данной точке.  
→ «Зависание» (q_shift плато) ↔ нерегулярная локальная геометрия (режимное переключение).

**Г6:** LWR в высоком p_fit нестабилен при малом |Y_mean| соседей — усиливает шум.  
→ Проверить: при каком соотношении |Y_mean| / std(Y) LWR даёт ошибку знака? Возможно, нужен ridge или ограничение на p_fit при низком signal-to-noise.
