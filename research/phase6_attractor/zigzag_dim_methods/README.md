# zigzag_dim_methods — Оптимальная размерность вложений событийного зигзага

## 1. Гипотезы

- **Г1.** Событийная структура зигзага имеет конечную интринзик-размерность d < p_max, которая выявляется геометрическими методами (TwoNN, MLE).
- **Г2.** При увеличении p сверх оптимального D₂ перестаёт расти — признак насыщения вложения.
- **Г3.** FNN не падает до нуля (ожидаемо: стохастический ряд), но имеет минимум или перегиб, совпадающий с оценками TwoNN/MLE.
- **Г4.** Объединение T=4% + T=0.4% не меняет размерность принципиально (оба масштаба — одна структура), но расширяет облако и снижает дисперсию оценок.
- **Г5.** Шум (Gaussian + shuffle) демонстрирует d ≈ p и D₂ ≈ p — нет насыщения.

## 2. Концепции, терминология, обозначения

| Обозначение | Смысл |
|---|---|
| T_BIG | Порог зигзага крупного масштаба (4%) |
| T_SMALL | Порог зигзага мелкого масштаба (0.4%) |
| pivot | Пивот зигзага — экстремум (хай H или лоу L) |
| X[i] | Событийный вектор задержек для i-го пивота |
| hybrid embedding | X[i] = [price_i, lr₁, lr₂, ...], lr_k = log(p_{i-k+1}/p_{i-k}) |
| p | Размерность вложения (число лагов) |
| d | Интринзик-размерность — «истинное» число степеней свободы |
| per-field z-score | Нормировка каждого поля вектора отдельно (mu/std по всему облаку) |
| per-step norm | Нормировка по пулу на каждом шаге walk-forward (режим прогноза) |
| drift | Изменение mu/sigma пула от step к step |

**Методы:**

- **FNN** (Kennel 1992) — для каждой точки ряда ищем ближайшего соседа в p-мерном вложении; если при переходе p→p+1 сосед «убегает» (расстояние скачет), он «ложный». Доля FNN% → 0 при полном развёртывании аттрактора. Для стохастики FNN% > 0 всегда — смотрим на минимум кривой.
  - **R-only:** критерий ratio = d_{p+1}/d_p > R_thr (без порога A).
  - **R+A:** критерий R ИЛИ абсолютный скачок d_{p+1}/std_z > A_thr.
  - **A-only:** только абсолютный критерий.

- **TwoNN** (Facco 2017) — для каждой точки облака: μ = r₂/r₁ (2-й ближайший / 1-й). d̂ = 1/E[log μ]. Геометрическая оценка интринзик-размерности. Не использует временну́ю структуру.

- **MLE Левины-Бикеля** (Levina & Bickel 2004) — обобщение TwoNN на k соседей:
  `d̂(x, k) = [(k−1) / Σⱼ₌₁ᵏ⁻¹ log(rₖ/rⱼ)]`
  Глобальная оценка = среднее по всем точкам. Sweep k=[3,5,10,20,50].
  Локальная версия: применяем в скользящем окне по событийному времени → показывает устойчивость d во времени.

- **D₂** (Grassberger-Procaccia 1983) — корреляционная размерность: наклон log C(r) vs log r. Для шума D₂ ≈ p; для структуры D₂ < p и насыщается.

## 3. Методология

**Данные:** SBER 10m, зигзаг по high/low (каузальный).

**Конфигурации данных:**

| Конфиг | Описание | ~N пивотов |
|---|---|---|
| t4_all | T=4%, H+L вместе | ~793 |
| t4t04_all | T=4% + T=0.4%, H+L вместе | ~793 + ~40870 |
| t4_H | T=4%, только хаи | ~397 |
| t4_L | T=4%, только лои | ~396 |
| t4t04_H | T=4%+T=0.4%, только хаи | ~397 + ~20435 |
| t4t04_L | T=4%+T=0.4%, только лои | ~396 + ~20435 |
| noise_gauss | Gaussian white noise (N ≈ t4_all, σ = σ_real) | ~793 |
| noise_shuf | Shuffled-surrogate t4_all | ~793 |

**Вложение:** hybrid X[i] = [price_i, lr₁, lr₂, ..., lr_{p-1}], где lr_k = log(price_{i-k+1}/price_{i-k}). Для H-only и L-only: строим по подпоследовательности только этого типа пивотов.

**Нормализация:**
- Для всех методов диагностики: **глобальная per-field z-score** (mean/std по всему облаку конфигурации).
- Дополнительно: диагностика дрейфа per-step нормировки — как mu/sigma поля 0 и поля 1 меняются с ростом пула.

**FNN-специфика:**
- FNN требует временно́й структуры (порядок событий). Применяется к последовательному ряду пивотов.
- После per-field глобальной нормировки: std_z = 1 для каждого поля, поэтому A_thr = 2 означает "скачок > 2σ поля".
- Три варианта (R-only / R+A / A-only) × четыре R_thr = [5, 10, 15, 20].

**TwoNN и MLE:** применяются к облаку точек (временно́й порядок не нужен). Sweep по p = 1..12. Для каждого p берём первые p столбцов нормированной матрицы вложений.

**D₂:** при N > 2000 — subsample 2000 (random seed=42). Sweep по p = [1, 2, 3, 5, 8, 12].

**Шум:**
- `noise_gauss`: N(mean_price, std_price) → строим hybrid вложение как для реальных данных.
- `noise_shuf`: перемешиваем реальные пивоты t4_all (np.random.default_rng(42).shuffle).

## 5. Критика постановки

1. **Событийный зигзаг ≠ детерминированный аттрактор.** FNN не даст нуля. Ориентируемся на минимум/перегиб кривой.

2. **T=4% + T=0.4% — иерархические данные.** Пивоты T=0.4% включают все пивоты T=4%. При объединении создаётся бимодальное распределение lr₁ (мелкие: ~±0.004, крупные: ~±0.04). Per-field sigma смешивает масштабы: T=0.4% в 50× больше, поэтому sigma(lr₁) формируется ими. T=4% пивоты в нормированном пространстве имеют аномально большие lr₁. Это нужно диагностировать (выводим sigma каждого поля).

3. **H vs L при смешанном пуле.** В hybrid вложении: для хая lr₁ = log(H/L_prev) > 0, для лоя lr₁ = log(L/H_prev) < 0. Смешанное облако двухкластерное. TwoNN/MLE могут завысить d. При разделении — вдвое меньше данных, MLE менее устойчив.

4. **Per-step нормировка в прогнозе.** При изменении пула (растёт окно) mu/sigma меняются. Это изменяет геометрию пространства поиска соседей. Диагностика показывает, насколько это критично.

5. **k для MLE.** При малых k — bias из-за кривизны пространства. При больших k — bias из-за глобальной неоднородности. Нужен sweep. Устойчивость d по k = мера надёжности.

## 7. Анализ и выводы

### 7.1 Диагностика данных

**Sigma полей (важно):**

| config | σ_price | σ_lr1 |
|---|---|---|
| t4_all | 78.4 | 0.106 |
| t4t04_all | 83.2 | 0.020 |
| noise_gauss | 77.5 | 6.69 |
| noise_shuf | 78.6 | 0.724 |

Критический факт: T=4% + T=0.4% снижает σ_lr1 с 0.106 до 0.020 (в 5.2 раза).
При per-field нормировке T=4% пивоты в объединённом пуле имеют ~5× увеличенный lr1
в нормированном пространстве. Это создаёт бимодальное облако — важное предупреждение
для методов измерения расстояний в таком пуле.

**Дрейф per-step нормировки:**
- σ_price дрейфует сильно: std(μ_price)=29.3 (~37% от σ_price) — долгосрочный тренд SBER.
- σ_lr1 стабильна: std(μ_lr1)=0.00145.
Вывод: поле price нестабильно нормируется от step к step. Геометрия поиска соседей
по price меняется с историческим периодом. Это подтверждает, что lr-поля (не price)
должны нести основную нагрузку при поиске соседей.

**noise_gauss некорректен:** σ_lr1=6.69 (63× больше реального). Gaussian noise из
N(mean, std) создаёт случайные скачки цен, не похожие на зигзаг. Этот контроль
занижен для FNN (высокий FNN), завышен для TwoNN/D₂ при малом p. Использовать
только для качественного сравнения. **noise_shuf — правильный контроль** (σ_lr1=0.724,
реалистичный разброс из реальных пивотов).

### 7.2 FNN

| config | p_min_frac | min_frac |
|---|---|---|
| t4_all | 7 | 0.009 |
| t4t04_all | 11 | 0.003 |
| t4_H | 8 | **0.000** |
| t4_L | 5 | 0.019 |
| noise_gauss | 7 | 0.035 |
| noise_shuf | 5 | **0.000** |

**Г1 (FNN) — частично подтверждена, но с оговоркой:**
noise_shuf даёт FNN=0 при p=5 — шум тоже "проходит" FNN.
Причина: при большом p облако случайного ряда становится равноудалённым (curse of
dimensionality), ratio d_{p+1}/d_p ≈ 1, FNN→0 вне зависимости от наличия структуры.
**FNN не различает структуру от перемешанного шума** — подтверждает исходный скептицизм.

### 7.3 TwoNN

TwoNN d(p=3): t4_all=2.725, noise_gauss=3.026, noise_shuf=2.998.
Все конфигурации (реальные и шумовые) дают d≈2.7-3.0 при p=3 — слабое разделение.
TwoNN при N=765, p=3 не является надёжным различителем из-за малого N и Concentration of Measure.

### 7.4 MLE Левины-Бикеля

d(p=3, k=10): 3.1-3.5 для всех конфигураций, d_std=1.3-1.8.
Высокая дисперсия указывает на недостаточный N. Метод неустойчив при N≈765.
При N=41К (t4t04_all): d=3.331, d_std=1.295 — ненамного лучше.
**Вывод: MLE-LB при наших объёмах данных слишком шумный для надёжной оценки.**

### 7.5 D₂ (Grassberger-Procaccia) — ключевой результат

```
config       p=1    p=2    p=3    p=5    p=8   p=12
t4_all      0.888  1.470  1.479  1.512  1.396  1.175   ← насыщение p=2-5
t4t04_all   0.819  1.486  1.598  1.572  1.531  1.499   ← насыщение p=2-3
t4_H        0.886  1.550  2.031  2.874  3.846  4.582   ← рост (N=377, мало данных!)
t4_L        0.886  1.536  2.032  2.876  3.755  4.446   ← рост (N=377, мало данных!)
noise_shuf  0.881  1.492  1.910  2.686  3.532  4.346   ← рост, нет насыщения ← ШУМ
noise_gauss 0.957  1.020  1.080  1.025  0.726  0.673   ← аномальное падение (некорр.)
```

**Г2 (D₂ насыщение) — подтверждена для t4_all и t4t04_all:**
- Насыщение D₂ ≈ 1.5 при p=2-3 (t4_all), p=2-5 (t4t04_all).
- noise_shuf: D₂ растёт монотонно → нет насыщения → шум правильно идентифицирован.
- **D₂ — единственный метод, надёжно различающий структуру от шума.**

**Проблема с t4_H и t4_L:** N=377 точек при p=12 → curse of dimensionality в D₂.
D₂ растёт с p, имитируя шум. Это не отсутствие структуры, а недостаток данных.
Рекомендуется использовать только t4t04_H/L (N~21K) для разделения хай/лоу.

**D₂ ≈ 1.5 — интринзик-размерность аттрактора:**
При p=3 (или p=2) D₂ уже насыщается. Это значит: оптимальное вложение p=3.
Физический смысл: структура "аттрактора" зигзага ~1.5-мерна (фрактальная).

### 7.6 Сравнение методов

| Метод | Различает сигнал от шума? | Надёжность при N≈765 | Оптимальное p |
|---|---|---|---|
| FNN | Нет (shuf тоже =0) | низкая | — |
| TwoNN | Нет (d≈2.7-3.0 для всех) | низкая | — |
| MLE-LB | Нет (слишком шумный) | очень низкая | — |
| **D₂** | **Да** (насыщение vs рост) | **высокая при N≥2K** | **p=3** |

**Главный вывод: для событийной структуры зигзага D₂ — единственный надёжный метод
оценки размерности вложения. Оптимальное p = 3 (насыщение D₂ при p=2-3).**

## 8. Дальнейшие направления

1. **D₂ с большим subsample:** текущий subsample=2000 → ограничивает точность
   при больших N. Увеличить до 5000-10000 для t4t04_all.

2. **t4_H/L только с t04 пулом:** при N=377 D₂ ненадёжна. Использовать t4t04_H/L
   (N~21K) как основную конфигурацию для H/L-разделения.

3. **noise_gauss — исправить:** генерировать шум как random walk в lr-пространстве:
   lr_i ~ N(0, σ_lr) → price_i = price_0 × exp(cumsum(lr)). Это даст σ_lr = σ_lr_real.

4. **Другие масштабы T:** повторить для T=2%, T=1% чтобы проверить,
   что p=3 — универсальный оптимум.

5. **Форкастинговая верификация:** проверить, что rMAE минимален именно при p=3
   (walk-forward sweep), и совпадает с D₂-насыщением.

6. **Локальный D₂:** разбить историю на скользящие окна и проверить, стабильна ли
   D₂ ≈ 1.5 во времени.
