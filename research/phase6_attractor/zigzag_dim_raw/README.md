# zigzag_dim_raw — Зигзаг на сырых ценах: FNN-диагностика и LWR-прогноз

## 1. Гипотезы

**Г1.** Зигзаг high/low (HIGH для пиков, LOW для впадин) на сырых ценах SBER формирует аттрактор конечной размерности, измеримой через FNN.

**Г2.** Раздельное вычисление FNN для восходящих (H) и нисходящих (L) пивотов даёт более чистый сигнал, чем на смешанном ряду (поскольку H и L — разные геометрические объекты).

**Г3.** Существует оптимальный порог T зигзага (по rMAE прогноза), при котором LWR наилучшим образом предсказывает следующий пивот.

**Г4 (фрактальность).** Объединение пивотов 1d(T=4%) и 10m(T=0.4%) в единый пул увеличивает покрытие аттрактора и улучшает прогноз. Мелкие события структурно подобны крупным — они являются частью того же событийного аттрактора.

**Г5.** 1h добавляет ценность поверх 1d+10m.

---

## 2. Концепции, терминология, обозначения

| Обозначение | Значение |
|---|---|
| **T** | Порог зигзага, % от цены. Пивот подтверждается при отклонении ≥ T |
| **p** | Размерность вложения. Вектор признаков X[i] = [price[i], log(price[i]/price[i-1]), ..., log(price[i-p+2]/price[i-p+1])] |
| **K** | Число ближайших соседей в LWR. K = 3·(p+1) |
| **H=1** | Горизонт прогноза: следующий пивот |
| **FNN** | False Nearest Neighbors (Kennel 1992). R_thr=15, A_thr=2.0. p_min = первый p при котором FNN=0 |
| **rMAE** | Relative MAE = mean\|pred−actual\| / mean\|Δprice\| (нормировка на средний ход цены) |
| **M0** | Наивная модель «следующий пивот = текущий» (random walk) |
| **LWR** | Locally Weighted Regression: k ближайших соседей, Гауссова полоса ξ = dist до k-го соседа, WLS |
| **T_prim** | Порог зигзага основного (1d) ряда |
| **T_aux** | Порог зигзага вспомогательного (1h или 10m) ряда |
| **Событийный аттрактор** | Аттрактор в пространстве событий (пивотов), а не в clock-time. Мелкие события (10m) — малые части того же аттрактора, что крупные (1d) |

## 3. Методология и протокол

### Зигзаг (find_pivots_hl)
Торговый стандарт: HIGH для пиков, LOW для впадин. Пивот подтверждается при развороте ≥ T·ext_val. Функция возвращает `(bar_idx, price, 'H'/'L')`.

### FNN-диагностика
- Вычисляется отдельно для H-пивотов и L-пивотов
- Вектор вложения: `X[i] = [z[i], log(z[i]/z[i-1]), ..., log(z[i-p+2]/z[i-p+1])]`
- p_min = первый p при котором FNN == 0.0 (не < порога, а точно ноль)
- Для объединённого пула: пивоты сортируются по дате, без per-TF нормализации

### LWR walk-forward
- Пул: все j < step с валидными признаками и целевой ценой (строго причинный)
- Aux пул: CE = searchsorted(dates_aux, cur_date, side="left") — жёсткая каузальная граница
- Нормировка признаков внутри lwr_pred: mu/sigma по всему пулу запроса (joint)
- Нет TRAIN_WIN: LWR взвешивает по близости сам

### Walk-forward схема
```
для каждого step ∈ [MIN_HISTORY, n-H):
    X_pool = {j < step, X[j] ≠ NaN, j+H < n}  (причинный)
    + aux: {j_aux < CE, X_aux[j_aux] ≠ NaN, j_aux+H < n_aux}
    pred = LWR(X_pool, y_pool, X[step], K)
    actual = prices[step + H]
```

## 5. Критика постановки

- **p=3 оптимально для LWR несмотря на FNN p_min=5-6**: свип p=3..9 показал монотонный рост rMAE с p. FNN и LWR оптимизируют разные цели — раскрытие аттрактора vs. качество прогноза при конечном пуле.
- **Только SBER 1d**: обобщаемость на другие тикеры не проверена.
- **Единственная метрика rMAE на SBER**: нет мультитикерного контроля.
- **Параметр K = 3(p+1)**: теоретически обоснован (ξ ≥ 3(p+1)), но не оптимизировался.
- **Горизонт H=1**: единственный практически реализуемый горизонт в событийном времени (H=2 требует прогноза промежуточного пивота).

### 6.6 FNN с метрикой amp_cos: свип T×α (zigzag_fnn_ampcos_sweep.py)

Метрика: `d(x,q) = α·|log(‖x‖/‖q‖)|_norm + (1−α)·(1−cos(x,q))_norm`.
NN ищется по custom metric; FNN-критерий — стандартный Kennel (Euclidean ratio + abs). H/L — раздельно. Свип: T∈{1.0%..8.5%}, α∈{0.0..1.0}.

**Результат:** p_min=2–3 устойчиво при α∈{0.1..1.0} для всех T. При α=0 (чистый косинус) FNN не достигает нуля в P_MAX=15 (помечено `?`) — метрика вырождена, потому что цена (~300) доминирует над лог-доходностями (~0.01) в норме вектора, и косинусное расстояние оказывается близко к нулю для всех пар. Это подтверждает, что p_min=3 — устойчивое свойство аттрактора, не зависящее от метрики. Файлы: `results/fnn_ampcox_sweep.csv`, `results/fnn_ampcox_sweep.png`.

## 7. Анализ и выводы

**Г1 — подтверждена.** Зигзаг на сырых ценах SBER имеет конечную размерность (p_min=3 для 1d H/L).

**Г2 — подтверждена.** Раздельный FNN для H и L необходим: смешанный ряд или неправильное разбиение даёт ложные результаты (плато FNN).

**Г3 — подтверждена.** Чёткий минимум rMAE при T=4% на 1d: 0.4895 (−51.1% vs M0). Диапазон T=2.5%–4% устойчив.

**Г4 — подтверждена.** Добавление 10m пула даёт −7.1% к rMAE (0.4895→0.4548). FNN на объединённом пуле достигает нуля (p_min=5-6), что подтверждает структурное единство аттрактора. **Ключевое методическое наблюдение:** пивоты 1d и 10m образуют *событийный аттрактор* — каждое событие (разворот зигзага) значимо вне зависимости от временного масштаба. Нормализация мелких событий до масштаба крупных разрушает эту иерархию и превращает структуру в стохастику. Правило: **сырые цены, без per-TF нормализации**.

**Г5 — отклонена.** 1h не улучшает 1d+10m ни при каком T_1h. Вероятная причина: 1h слишком близок по масштабу к 1d (T в 10x разнице vs 10m в 100x разнице).

**Свип p (zigzag_p_sweep.py).** p=3 оптимально для LWR, несмотря на FNN p_min=5-6. Причина: FNN и LWR измеряют разное. FNN определяет минимальное p для *геометрического раскрытия* аттрактора (устранения ложных соседей). LWR оценивает p для *прогнозирования* — и здесь проклятие размерности перевешивает: с ростом p растёт K=3·(p+1), пул становится всё более разреженным в высоких размерностях, а дополнительные лаги log-return добавляют шум без сигнала. Два разных оптимума для двух разных задач — ожидаемое поведение.

**Метрика расстояния (zigzag_lwr_ampcos_sweep.py).** Четыре варианта custom-метрики (amp_cos, blend, split, split_norm) хуже стандартного L2 при любом α. Причина доминирования цены: в X=[price, lr1, lr2] норма вектора ≈ price (~300), лог-доходности (~0.01) несравнимо малы. Косинусное расстояние по полному вектору вырождается. split_norm (z-score → d_amp по норм. цене, d_shape по норм. lr) дал лучший результат среди custom-метрик (rMAE=0.5295), но не превзошёл L2 (0.5031). Вывод: **стандартный L2 с joint z-score нормировкой — оптимальная метрика для текущего вложения**.

**FNN с custom metric (zigzag_fnn_ampcos_sweep.py).** p_min=2–3 устойчиво при α∈{0.1..1.0} для всех T. α=0 (чистый косинус) — вырожденный случай: FNN не достигает нуля. Вывод: **p_min=3 — устойчивое геометрическое свойство аттрактора, независимое от метрики**.

**Вложение (zigzag_embed_compare.py).** Абсолютная цена в X[0] критически важна: без неё rMAE +5.8% (diff_only p=2) или +2.2% (diff_only p=3). Ratio вместо цены даёт +52.9% из-за несоответствия шкал при реконструкции. Согласуется с norm_study: raw > log_swing > ratio. **Итоговое вложение X=[price, lr1, lr2], p=3 — подтверждено как оптимальное**.

**Оптимальный K и ансамблирование (§6.12–6.14).** Правило K=3(p+1)=12 занижено при пуле 42K. Оптимум K=50 (U-кривая). S-map θ=10 — сильная альтернатива (мягкое глобальное взвешивание vs жёсткий KNN). Ансамбль LWR K=50 + S-map θ=10, α=0.65 даёт rMAE=0.4143 — на 8.9% лучше исходного LWR K=12. Механизм: два разных механизма взвешивания → частично независимые ошибки → variance reduction при смешении.

**Zeroth-order методы неприменимы к смешанному пулу (§6.13, 6.16).** NW, RBF, Simplex дают rMAE > 1.0. Общая причина: усреднение абсолютных целевых цен из разномасштабного пула (1d swing ±4%, 10m swing ±0.4%). Degree-1 линейная модель LWR обходит это через price-коэффициент. Zeroth-order требует нормализованных целей (log-return).

**LP-коррекция: ценовое vs log-return пространство (§6.17–6.18).** LP в абсолютном ценовом пространстве деструктивна (SVD выделяет исторические ценовые уровни). LP в log-return пространстве (P_LP=6, d=2, k=10) даёт +1.4% к ансамблю. Оптимальный d=2, а не 3 (FNN) — в локальной окрестности k=10 log-return аттрактор 2-мерен. Правило: **LP работает в масштаб-инвариантном пространстве** (ratio в app3, log-return здесь).

**Октавный каскад (zigzag_cascade_sweep.py).** Строгий каскад (cascade_algorithm.md) применён к зигзагу: уровни p_fit×{1,2,4,8,16}, пул 1d+1h+10m. Результат: монотонное ухудшение с каждым уровнем (+3% при N=2, +71.7% при N=5). Алгоритм адаптирован корректно: суб-вектор X_p_next[j−k] содержит только пивоты из окна X_p[j], вложенность соблюдена. Причина деградации — несоответствие масштабов между 1d-запросом и 10m-пулом в многомерном пространстве: при p=48 log-доходности 1d (~2% за пивот) и 10m (~0.2%) отличаются в 10 раз, z-score нормировка по совместному пулу (доминирует 10m) делает K=12 ближайших на первом уровне случайными относительно запроса. Строгая воронка закрепляет ошибку первого уровня. Каскад эффективен, когда пул масштабно однороден (как att-сигнал или Лоренц); для разномасштабного событийного пула он неприменим в данной конфигурации.

### 6.12 Расширенный свип K + S-map θ-свип (zigzag_lwr_k_extended.py, zigzag_smap_sweep.py)

### 6.13 LWR vs NW vs RBF (zigzag_lwr_vs_rbf.py)

Свип K=6..30, те же условия. NW (degree-0, weighted avg) и RBF (interpolation) дают rMAE > 1.0 — хуже наивного M0.  
**Причина:** обе модели усредняют абсолютные цены y из смешанного 1d+10m пула. Цели 10m (~300±1.2₽ swing) и 1d (~300±12₽) смешиваются → среднее смещается к текущей цене → систематическая недооценка следующего хода. **LWR (degree-1) этой проблемы не имеет**: линейная модель ŷ=c₀+c₁·price+... масштабирует предсказание через price-коэффициент. Вывод: **degree-1 модель обязательна при смешанном пуле с разными масштабами свингов**.

### 6.17 LP-коррекция v1-v2: провал (zigzag_lp_correction.py, zigzag_lp_correction2.py)

LP-коррекция применялась к предсказанному вектору X_pred = [ŷ, lr1_pred, lr2_pred, ...] в абсолютном ценовом пространстве. Результат: rMAE=0.9–2.1 (катастрофа) при всех k_lp∈{5..50} и d_lp∈{1..6}.

Тот же эффект, что NW/Simplex. Единственное исключение: d=6 в P_LP=7 при k=5 — вырожденный SVD (rank=4 < d=6) → тождественное преобразование (rMAE = raw). Файлы: `results/lp_correction.csv`, `results/lp_correction2.csv`.

### 6.19 LWR-abs vs LWR-log: целевое пространство (zigzag_lwr_logret.py, zigzag_lwr_logret_psweep.py)

Признаки X=[price, lr1, ..., lr(p-1)] одинаковы. Свип K=6..500 и p=2..8.

**K-свип при p=3:**

|---|---|---|---|
| 50 | **0.4194** | 0.4252 | abs |
| 75 | 0.4254 | **0.4231** | log |
| 500 | 0.4629 | **0.4338** | log |

Перекрёст на K≈75. При K=50 (рабочая точка) LWR-abs лучше. При K≥75 LWR-log устойчивее: масштаб-инвариантные цели не деградируют при гетерогенных соседях.

**p-свип:** по всем p∈{2,3,4,5,6,8} LWR-abs побеждает в своей рабочей точке (p=3 K=50 → 0.4194 — глобальный оптимум). LWR-log при малом K+большом p численно нестабилен (p=4 K=6: rMAE=4.5 — взрыв через exp при почти вырожденном WLS).

Simplex: k=p+1 соседей, веса `w_i=exp(−d_i/d_1)`, восстановление `ŷ=p_cur·exp(Σwᵢ·lrᵢ)`. Свип p=2..8.

## 7. Анализ и выводы

**Г1 — подтверждена.** Зигзаг на сырых ценах SBER имеет конечную размерность (p_min=3 для 1d H/L).

**Г2 — подтверждена.** Раздельный FNN для H и L необходим: смешанный ряд или неправильное разбиение даёт ложные результаты (плато FNN).

**Г3 — подтверждена.** Чёткий минимум rMAE при T=4% на 1d: 0.4895 (−51.1% vs M0). Диапазон T=2.5%–4% устойчив.

**Г4 — подтверждена.** Добавление 10m пула даёт −7.1% к rMAE (0.4895→0.4548). FNN на объединённом пуле достигает нуля (p_min=5-6), что подтверждает структурное единство аттрактора. **Ключевое методическое наблюдение:** пивоты 1d и 10m образуют *событийный аттрактор* — каждое событие (разворот зигзага) значимо вне зависимости от временного масштаба. Нормализация мелких событий до масштаба крупных разрушает эту иерархию и превращает структуру в стохастику. Правило: **сырые цены, без per-TF нормализации**.

**Г5 — отклонена.** 1h не улучшает 1d+10m ни при каком T_1h. Вероятная причина: 1h слишком близок по масштабу к 1d (T в 10x разнице vs 10m в 100x разнице).

**Свип p (zigzag_p_sweep.py).** p=3 оптимально для LWR, несмотря на FNN p_min=5-6. Причина: FNN и LWR измеряют разное. FNN определяет минимальное p для *геометрического раскрытия* аттрактора (устранения ложных соседей). LWR оценивает p для *прогнозирования* — и здесь проклятие размерности перевешивает: с ростом p растёт K=3·(p+1), пул становится всё более разреженным в высоких размерностях, а дополнительные лаги log-return добавляют шум без сигнала. Два разных оптимума для двух разных задач — ожидаемое поведение.

**Метрика расстояния (zigzag_lwr_ampcos_sweep.py).** Четыре варианта custom-метрики (amp_cos, blend, split, split_norm) хуже стандартного L2 при любом α. Причина доминирования цены: в X=[price, lr1, lr2] норма вектора ≈ price (~300), лог-доходности (~0.01) несравнимо малы. Косинусное расстояние по полному вектору вырождается. split_norm (z-score → d_amp по норм. цене, d_shape по норм. lr) дал лучший результат среди custom-метрик (rMAE=0.5295), но не превзошёл L2 (0.5031). Вывод: **стандартный L2 с joint z-score нормировкой — оптимальная метрика для текущего вложения**.

**FNN с custom metric (zigzag_fnn_ampcos_sweep.py).** p_min=2–3 устойчиво при α∈{0.1..1.0} для всех T. α=0 (чистый косинус) — вырожденный случай: FNN не достигает нуля. Вывод: **p_min=3 — устойчивое геометрическое свойство аттрактора, независимое от метрики**.

**Вложение (zigzag_embed_compare.py).** Абсолютная цена в X[0] критически важна: без неё rMAE +5.8% (diff_only p=2) или +2.2% (diff_only p=3). Ratio вместо цены даёт +52.9% из-за несоответствия шкал при реконструкции. Согласуется с norm_study: raw > log_swing > ratio. **Итоговое вложение X=[price, lr1, lr2], p=3 — подтверждено как оптимальное**.

**Оптимальный K и ансамблирование (§6.12–6.14).** Правило K=3(p+1)=12 занижено при пуле 42K. Оптимум K=50 (U-кривая). S-map θ=10 — сильная альтернатива (мягкое глобальное взвешивание vs жёсткий KNN). Ансамбль LWR K=50 + S-map θ=10, α=0.65 даёт rMAE=0.4143 — на 8.9% лучше исходного LWR K=12. Механизм: два разных механизма взвешивания → частично независимые ошибки → variance reduction при смешении.

**Zeroth-order методы неприменимы к смешанному пулу (§6.13, 6.16, 6.20).** NW, RBF, Simplex-abs дают rMAE > 1.0. Общая причина: усреднение абсолютных целевых цен из разномасштабного пула (1d swing ±4%, 10m swing ±0.4%). Degree-1 линейная модель LWR обходит это через price-коэффициент. **Исправление: log-return цель.** Simplex-log (y=log(p_next/p_cur)) масштаб-инвариантен и при p=8 достигает rMAE=0.4238.

**LP-коррекция: ценовое vs log-return пространство (§6.17–6.18).** LP в абсолютном ценовом пространстве деструктивна (SVD выделяет исторические ценовые уровни). LP в log-return пространстве (P_LP=6, d=2, k=10) даёт +1.4% к ансамблю. Оптимальный d=2, а не 3 (FNN) — в локальной окрестности k=10 log-return аттрактор 2-мерен. Правило: **LP работает в масштаб-инвариантном пространстве** (ratio в app3, log-return здесь).

**Октавный каскад (zigzag_cascade_sweep.py).** Строгий каскад (cascade_algorithm.md) применён к зигзагу: уровни p_fit×{1,2,4,8,16}, пул 1d+1h+10m. Результат: монотонное ухудшение с каждым уровнем (+3% при N=2, +71.7% при N=5). Алгоритм адаптирован корректно: суб-вектор X_p_next[j−k] содержит только пивоты из окна X_p[j], вложенность соблюдена. Причина деградации — несоответствие масштабов между 1d-запросом и 10m-пулом в многомерном пространстве: при p=48 log-доходности 1d (~2% за пивот) и 10m (~0.2%) отличаются в 10 раз, z-score нормировка по совместному пулу (доминирует 10m) делает K=12 ближайших на первом уровне случайными относительно запроса. Строгая воронка закрепляет ошибку первого уровня. Каскад эффективен, когда пул масштабно однороден (как att-сигнал или Лоренц); для разномасштабного событийного пула он неприменим в данной конфигурации.

**Три масштаба одного аттрактора (§6.21–6.22).** Ключевая концептуальная находка: каждый метод ансамбля смотрит на событийный аттрактор в разном масштабе близости:

- **Simplex-log** (k=9): ультра-локальный — буквально 9 ближайших прецедентов. Zeroth-order среднее их лог-доходностей.
- **LWR** (K=50, Гауссово ядро): средний масштаб — 50 соседей с мягким взвешиванием, линейная интерполяция.
- **S-map θ=1**: глобальный — вырождается в OLS на всём пуле (~42K точек). Улавливает линейный тренд между признаками и целью по всей истории.

Именно различие масштабов обеспечивает декоррелированность ошибок: каждый метод «видит» разную часть информации аттрактора. При θ≥20 S-map локализуется и дублирует LWR → оптимизатор исключает его (α_sm=0). При θ=1 S-map максимально отличен от остальных → максимальный вклад в ансамбль. Это объясняет парадокс: худший S-map в одиночку (θ=1, rMAE=0.54) — лучший S-map в ансамбле.

### §8.4 Масштаб событий определяется T, а не таймфреймом (`zigzag_10m_t4_forecast.py`)

**Результат:** T=4% на 10m и T=4% на 1d — один и тот же аттрактор.
- `only_t4` (10m T=4%, без фрактала): rMAE=0.3960 при пуле avg=410 — практически идентично 1d+10m (0.3963 при пуле 13 211)
- `plus_frac` (+ T=0.4% фрактал): rMAE=0.3935 (+0.64% улучшение)

**Ключевые выводы:**

1. **Событийный аттрактор определяется T (%), а не таймфреймом.** T=4% на 10m и T=4% на 1d захватывают одно и то же геометрическое объектание в пространстве событий. Это подтверждено: 63% пивотов совпадают по дате, и rMAE идентичен.

2. **Единый временно́й ряд предпочтительнее смешанного.** Брать события из одного ряда (10m → 10m T=4% + 10m T=0.4%) согласованнее, чем смешивать два TF (1d+10m). Преимущества:
   - Временна́я шкала единая → нет неоднозначности границ баров
   - Пивоты определены в одной гранулярности H/L
   - Лучший итоговый rMAE (0.3935 vs 0.3963)

3. **Обобщение за пределы финансов.** Метод применим к любому временному ряду с определённым понятием «значимого разворота» T. Параметр T задаёт масштаб событий; фрактальный пул — мелкие события того же ряда с меньшим T'. Финансовая специфика не используется — только структура событийного аттрактора.

**Зафиксированные параметры ансамбля:**

| Метод | p | второй параметр | чувствительность к p |
|---|---|---|---|
| LWR-abs | 3 (FNN 1d) | K=50 | высокая |
| RBF-log | 3 (совпало с LWR) | K=12 | высокая |
| Simplex-log | 8 (эмпирический оптимум) | — (k=p+1) | средняя (колокол) |
| S-map | 3 (≈6, нечувствителен) | θ=1 | низкая (плато p=4..12) |

**Веса 4-way ансамбля (устойчивый оптимум):**
`α_lwr≈0.08, α_sx≈0.33, α_sm=0.20, α_rbf≈0.40`

1. **⭐ Локальное обучение гиперпараметров** (наиболее перспективное направление — см. §8.2).
2. **Мультитикерная проверка**: результаты получены только на SBER. Проверить на GAZP, LKOH, GMKN — особенно важно для Simplex-log p=8 (эмпирический, не FNN). Предварительно следует реализовать локальное обучение, которое даст алгоритм переноса на другие тикеры.
3. **Уровень+ошибка как торговый сигнал**: прогнозируемая цена следующего пивота + ширина доверительного интервала — потенциальная основа для торгового сигнала (уровень разворота + неопределённость).
4. **Независимые H/L модели**: ансамбль прогнозирует «следующий пивот» без учёта направления. Раздельные модели для пиков и трогов могут учесть асимметрию. Наблюдение: HIGH→LOW (rMAE=0.3749) стабильно легче LOW→HIGH (rMAE=0.4178) — разница ~11%, воспроизводится во всех вариантах.

### §8.2 Закрытые направления (не дали улучшения)

**Раздельные модели по типу перехода (`zigzag_typed_models.py`):**
- `typed_pool`: пул фильтруется по типу пивота (HIGH→LOW vs LOW→HIGH). Результат: +0.80% (хуже). Пул уменьшается вдвое (~6605 vs 13211), потеря разнообразия превышает выигрыш от однородности.
- `type_feature`: тип ±0.5 добавлен в X как признак. Результат: +0.45% (хуже). Тип уже неявно закодирован в абсолютной цене; явное добавление вносит шум.
- Структурный факт: HIGH→LOW rMAE=0.3749, LOW→HIGH rMAE=0.4178 (~11% асимметрия) — воспроизводится во всех вариантах.

**Расширение признакового вектора (`zigzag_feature_expansion.py`):**
- `+inter`: добавлен log(интервал между пивотами в барах). Результат: +0.36% (нейтрально).
- `+pos_50/100/200`: добавлена позиция относительно MA. Результат: +1.26% / +1.71% / +4.49%. Чем длиннее MA — тем хуже. Причина: длинная MA кодирует режимную информацию (до/после 2022), создавая spurious patterns на ранних данных.
- Вывод: X=[price, lr1, lr2] уже оптимален. Абсолютная цена неявно несёт весь необходимый контекст.

### §8.3 Локальное обучение гиперпараметров ⭐

**Идея**: глобальные параметры ансамбля (p=3, T=4%, структура вложения) определяются геометрией событийного аттрактора и универсальны. Локальные параметры (K, веса α, θ) могут иметь оптимумы, зависящие от текущего состояния рынка.

**Алгоритм**: для каждого шага `step` оптимизировать гиперпараметры на скользящем окне W последних событий методом LOO или walk-forward mini-validation. Аналог — oracle per-origin в att-прогнозировании (фаза 5, скр.83-86) давал потолок −53% rMAE.

**Двойная ценность**:
1. Даже если локальный оптимум хуже глобального на SBER — алгоритм даёт рецепт калибровки на любой тикер без ручного подбора.
2. Если локальный оптимум лучше — прямое улучшение метрики.

**Ключевой вопрос**: какие параметры реально имеют per-origin оптимум? Кандидаты: K (число соседей), α-веса методов, θ S-map. Параметры, которые, вероятно, универсальны: p=3, T=4%, min_lag.

### §8.1 Задержка зигзага и момент получения прогноза (`zigzag_lag_analysis.py`)

**Вопрос**: на сколько баров зигзаг запаздывает? В какой момент можно получить прогноз следующего события?

**Перерисовки нет**: после записи пивот никогда не изменяется и не сдвигается. Алгоритм является causal по конструкции — до подтверждения незакрытый пик является кандидатом, а не сигналом.

**Результаты для SBER 1d T=4% (883 пивота):**

| Метрика | p25 | median | p75 | mean | max |
|---|---|---|---|---|---|
| **lag** (пик → подтверждение) | 1 | **1** | 2 | 2.0 | 20 |
| **gap** (подтверждение → след. пик) | 0 | **1** | 4 | 3.4 | 57 |
| **inter** (сигнал → след. сигнал) | 2 | **3** | 6 | 5.3 | 66 |

- `gap < 0` (следующий пик уже позади к моменту сигнала): **0.0%** — структурного опоздания нет.
- lag по типу: HIGH median=1 mean=2.1, LOW median=1 mean=1.8 — различия незначимы.

**Практический вывод**: в половине случаев подтверждение приходит уже на следующий бар после реального экстремума. После получения сигнала следующий пивот наступает медианно ещё через 1 бар (горизонт позиции 1–4 дня). Прогноз никогда не опаздывает структурно (gap ≥ 0 всегда). Схема пригодна для среднесрочной торговли на дневных данных.

**10m T=0.4% (41 223 пивота):** lag и gap аналогичны (median=1 бар), max lag=156 баров (редкие затяжные консолидации).
