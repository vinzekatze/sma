# Алгоритм каскадного поиска соседей (строгая воронка)

Никакого расширения задержек на уровнях каскада за пределы невыбранных задержек быть не должно. Каскад максимально строгий.
уровни каскада p_lv_N = p_fit * {1, 2, 4, 8, 16 ...}  (по умолчанию 4 уровня)

## Мотивация

Прогноз att строится через LWR: нужно найти xi_lwr «правильных» соседей для вектора запроса
размерности p_fit. Задача каскада — найти соседей, которые одновременно похожи на запрос
и в длинном контексте (p_lv_1 >> p_fit), и в коротком (p_fit). Простой однократный поиск
в p_fit-мерном пространстве не использует информацию о долгосрочном контексте.

---

## Уровни каскада

Октавные уровни (по умолчанию 4 уровня):

```
p_lv_1 = p_fit × 2^(N−1)   ← самый грубый
p_lv_2 = p_fit × 2^(N−2)
p_lv_3 = p_fit × 2^(N−3)
p_lv_N = p_fit              ← финальный (= LWR-уровень)
```

Пример, N=4, p_fit=9:

```
p_lv_1 = 72,  p_lv_2 = 36,  p_lv_3 = 18,  p_lv_4 = 9
```

---

## Алгоритм (одна итерация прогноза на 1 шаг)

### Уровень 1

**1. Поиск соседей.**
В глобальной библиотеке находим xi_lwr ближайших векторов размерности p_lv_1
к вектору запроса размерности p_lv_1. Поиск — L2-расстояние.

**2. Переразбивка каждого соседа.**
Каждый найденный вектор-сосед размерности p_lv_1 порождает набор суб-векторов
размерности p_lv_2 скользящим окном:

```
Сосед: {x(t), x(t+1), ..., x(t+p_lv_1−1)}

Суб-векторы:
  {x(t),   x(t+1),   ..., x(t+p_lv_2−1)}
  {x(t+1), x(t+2),   ..., x(t+p_lv_2)  }
  ...
  {x(t+p_lv_1−p_lv_2), ..., x(t+p_lv_1−1)}

Количество суб-векторов с одного соседа:
  p_lv_1 − p_lv_2 + 1
  = p_lv_2 + 1  (для октавного фактора ×2)
```

**3. Формирование пула.**
Суб-векторы от всех xi_lwr соседей объединяются в пул pull_lv_1,
повторы (по временному индексу) удаляются.

---

### Уровень k (общий случай)

**1. Поиск соседей.**
В пуле pull_lv_{k−1}, полученном от предыдущего уровня, находим xi_lwr ближайших
векторов размерности p_lv_k к вектору запроса размерности p_lv_k.

**2. Переразбивка.**
Каждый найденный вектор размерности p_lv_k порождает суб-векторы размерности p_lv_{k+1}:

```
Количество суб-векторов с одного соседа:
  p_lv_k − p_lv_{k+1} + 1
  = p_lv_{k+1} + 1  (октав)
```

**3. Формирование пула pull_lv_k.**
Объединение суб-векторов от всех xi_lwr соседей с дедупликацией.

---

### LWR-уровень (уровень N)

**1. Поиск соседей.**
В пуле pull_lv_{N−1} находим xi_lwr ближайших векторов размерности p_fit
к вектору запроса размерности p_fit.

**2. Прогноз.**
По найденным xi_lwr соседям строится LWR-прогноз на 1 шаг.

---

## Ключевые свойства алгоритма

### Строгая воронка — без расширения за пределы выбранных соседей

На каждом уровне пул формируется **только** из суб-векторов соседей, выбранных на
предыдущем уровне. Никакие точки библиотеки, не прошедшие отбор на уровне k,
не попадают в пул уровня k+1.

Это принципиально отличает алгоритм от версии с расширением (expansion), где
в пул добавлялись временны́е соседи выбранных точек (индексы i−1, i−2, ..., i−radius),
что фактически сбрасывало фильтр к почти полной библиотеке.

### p-aligned вложенность

Суб-вектор размерности p_lv_{k+1}, порождённый из соседа p_lv_k, является
**непрерывным срезом** реального временного ряда. Это гарантирует, что каждая
точка пула на уровне k+1 — это настоящий исторический паттерн длины p_lv_{k+1},
а не артефакт алгоритма.

### Единый параметр управления — xi_lwr

На всех уровнях каскада используется одно и то же количество соседей xi_lwr.
Отдельные параметры xi_search_lv_1, xi_search_lv_2, ... не нужны (доказательство ниже).

## Анализ размеров пулов

### Нотация

```
xi      = xi_lwr  (число соседей, одинаковое на всех уровнях)
r_k     = p_lv_k − p_lv_{k+1} + 1 = p_lv_{k+1} + 1  (октав)  — суб-векторов с одного соседа
```

### До дедупликации

```
pull_lv_k (max) = xi × r_k = xi × (p_lv_{k+1} + 1)
```

### После дедупликации — минимальный пул (худший случай)

Максимальное перекрытие достигается, когда все xi соседей стоят вплотную во времени:
позиции j, j+1, ..., j+xi−1.

Суб-векторы соседа на позиции j начинаются с j, j+1, ..., j+p_lv_{k+1}−1.
Суб-векторы соседа на позиции j+xi−1 начинаются с j+xi−1, ..., j+xi−1+p_lv_{k+1}−1.

Объединение: от j до j+xi−1+p_lv_{k+1}−1 — непрерывный диапазон длиной:

```
pull_lv_k (min) = xi + p_lv_{k+1}   (октав)
```

### Итоговые границы

```
xi + p_lv_{k+1}  ≤  pull_lv_k  ≤  xi × (p_lv_{k+1} + 1)
```

## Вывод: xi_lwr достаточен на всех уровнях

### Условие работоспособности каскада

Уровень k+1 должен найти xi соседей из пула pull_lv_k.
Необходимое условие: pull_lv_k ≥ xi.

### Доказательство

Даже в наихудшем случае (все соседи вплотную):

```
pull_lv_k (min) = xi + p_lv_{k+1} > xi
```

так как p_lv_{k+1} ≥ p_fit > 0 на любом уровне.

Следовательно, пул **всегда больше xi** — следующий уровень всегда найдёт
xi соседей. Условие выполняется на всех уровнях без исключения.

### Запас пула по уровням (пример: p_fit=9, xi=35, N=4)

| Уровень | p_lv | p_lv_{n+1} | min пул | запас над xi |
|---------|------|------------|---------|-------------|
| 1       | 72   | 36         | 35+36=71 | +36 (+103%) |
| 2       | 36   | 18         | 35+18=53 | +18 (+51%)  |
| 3       | 18   | 9          | 35+9=44  | +9  (+26%)  |
| LWR     | 9    | —          | —        | —           |

Запас тем больше, чем грубее уровень — это структурное свойство октавного каскада.

### Вывод

**xi_search = xi_lwr на всех уровнях** — корректный, достаточный и минимально
параметризованный выбор. Каскад управляется одним параметром xi_lwr; отдельные
xi_search_lv_k не нужны и не дают выигрыша в надёжности по сравнению с xi_lwr.

## Формулы для реализации

```python
# Уровни (октавный каскад, N уровней)
def cascade_levels(p_fit: int, n_levels: int) -> list[int]:
    return [p_fit * (2 ** (n_levels - 1 - k)) for k in range(n_levels)]
# Пример: p_fit=9, n_levels=4 → [72, 36, 18, 9]

# Суб-векторов с одного соседа при переходе p_lv → p_next
def n_subvectors(p_lv: int, p_next: int) -> int:
    return p_lv - p_next + 1

# Размер пула (min, worst case)
def pool_min(xi: int, p_next: int) -> int:
    return xi + p_next  # p_next = p_lv_{k+1}

# Размер пула (max, no dedup)
def pool_max(xi: int, p_lv: int, p_next: int) -> int:
    return xi * (p_lv - p_next + 1)
```

### Переразбивка соседа (суб-векторы)

```python
def expand_neighbor(neighbor: np.ndarray, p_next: int) -> np.ndarray:
    """
    Из вектора длины p_lv создаёт все суб-векторы длины p_next.
    neighbor: shape (p_lv,)
    Возвращает: shape (p_lv − p_next + 1, p_next)
    """
    p_lv = len(neighbor)
    n_sub = p_lv - p_next + 1
    return np.array([neighbor[i:i + p_next] for i in range(n_sub)])
```

## Открытые вопросы

1. **xi_search > xi_lwr на грубых уровнях**: формально не нужен для корректности,
   но может улучшить качество (шире охват на грубом уровне → больше кандидатов
   для тонкого). Требует отдельного эксперимента.

2. **N уровней**: при N=4 и p_fit=9 верхний уровень p_lv_1=72. При росте p_fit
   или N глобальная библиотека может стать меньше p_lv_1 → нужна проверка
   `len(library) ≥ p_lv_1`.

3. **Дедупликация**: в реализации — по временно́му индексу начала суб-вектора
   (а не по значению), что корректно и дёшево (O(n log n) через sorted set).

4. **Метрика поиска**: на всех уровнях L2. Альтернативы (косинусное расстояние,
   нормализованный L2) — отдельный вопрос.
